Sanitizer

上一篇的 Miri 能解释执行但很慢,也不能调 C 函数。Sanitizer 换了一条路:编译时在原生代码里插入检查,运行得快得多。这篇把常见的内存错误和数据竞争各跑一遍,看它们的报告长什么样、哪些在本机能用、代价多大。

5
本篇用 ASan 触发并报告的内存错误种类(释放后使用、堆越界、栈越界、重复释放、泄漏;另有 memcpy 越界)
×9.3
200 万次 Box::new:ASan 对原生 -O 的耗时倍数
2
本机不支持的 -Zsanitizer 值:leak、memory
← 上一篇 Miri 检查未定义行为

本步的对象

    本文用到的工具与边界

    • 本机 macOS 27 arm64 / rustc 1.98.1(brew)/ cargo 1.98.1;单个文件用 rustc 直接编译,需要依赖时用 cargo(经代理从 crates.io 下载);计时用 std::time::Instant,数字每次运行会有小幅抖动。nightly 工具链用 rustup 装在隔离目录(不影响 brew 的 rustc):rustc 1.101.0-nightly (21b707e3f 2026-09-30)、miri 0.1.0 (21b707e3f9 2026-09-30)。-Zsanitizer=address(直接用 rustc);-Zsanitizer=thread 配合 cargo -Zbuild-std(rust-src 组件);栈符号用 -Zunstable-options -C symbol-mangling-version=legacy 以便阅读
    • 没有验证:Linux 上的 sanitizer 行为与支持范围(例如 leak、memory)、-Zbuild-std 对 ASan 的影响(本篇的 ASan 没有重编标准库,因此标准库内部代码没有被插桩)、stack-use-after-return 与 stack-use-after-scope、ASAN_OPTIONS 的其它选项、sanitizer 与 Miri 同时使用
    • 本篇的调用栈只截取了前 3 帧、省略了 Shadow bytes 部分以便阅读;其余内容为原样输出
