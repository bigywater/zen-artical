Servlet Filter 链:请求如何经过多层处理

过滤器看起来就是 doFilter 前后各写点代码,但顺序、短路、响应是否已提交、派发类型与异步都有细节。这篇用真实的容器把每一个都跑出来。

声明顺序
过滤器链按声明顺序执行,精确路径的过滤器若后声明则在通配过滤器之后
500 vs 200
chain.doFilter 之后 setStatus(500):小响应生效,20 万字符的大响应已提交所以仍是 200 且 X-Late 头丢失
0 ms vs 361 ms
异步请求里过滤器的「后」执行时的经过时间与客户端实际等待时间

请求与响应的包装

实测 · 本机执行输出 
  [wrap]
  请求包装(改参数 / 头 / URI):200 “name=AMY;ua=FAKE-UA;path=/p(wrapped);len=-1” Content-Length=43
  响应包装(捕获 servlet 输出再改写):200 “HELLO FROM HELLO+EXTRA” X-Test=wrapped Content-Length=22
    事件:
        servlet hello 处理 /x 的 REQUEST
        捕获到 16 字节,改写后 22 字符;写回之前 isCommitted = false
  过滤器在 chain.doFilter 之后改状态码 / 头(响应小,可能已提交):状态 500;X-Late = 1;body “hello from hello”
    事件:
        servlet hello 处理 /x 的 REQUEST
        servlet 返回之后 isCommitted = false;再 setHeader("X-Late")
        再 setStatus(500) 之后 getStatus = 500
  大响应(20 万字符,响应已提交):状态 200;X-Late = (没有);body 长度 200000
    事件:
        大响应 servlet 返回之后 isCommitted = true
        再 setStatus(500) 之后 getStatus = 200
