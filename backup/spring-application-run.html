SpringApplication.run 的启动阶段与启动事件

应用启动时到底按什么顺序触发了哪些事件?@Component 里写的监听器为什么收不到 ApplicationStartingEvent?runner 在 Ready 之前还是之后跑?慢的 runner 会不会让端口一直关着?这篇在 Spring Boot 4.0.8 上把每个阶段都打了点。

10 / 6
addListeners 与 spring.factories 的监听器收到 10 个事件,@Component 的监听器只收到 6 个
5 → 6 → 56
ContextInitialized、Prepared、ContextRefreshed 三个时间点的 Bean 定义数
870 ms vs 2388 ms
外部客户端第一次连上端口,与 1500 ms 的慢 runner 结束,相差约 1500 ms

谁能收到哪些事件

实测 · 本机执行输出 
  [A] app.addListeners(...):共 10 个——ApplicationStarting、ApplicationEnvironmentPrepared、ApplicationContextInitialized、ApplicationPrepared、ContextRefreshed、ApplicationStarted、AvailabilityChange、ApplicationReady、AvailabilityChange、ContextClosed
  [B] @Component:共 6 个——ContextRefreshed、ApplicationStarted、AvailabilityChange、ApplicationReady、AvailabilityChange、ContextClosed
  [C] spring.factories 的 ApplicationListener:共 10 个——ApplicationStarting、ApplicationEnvironmentPrepared、ApplicationContextInitialized、ApplicationPrepared、ContextRefreshed、ApplicationStarted、AvailabilityChange、ApplicationReady、AvailabilityChange、ContextClosed
  [R] spring.factories 的 SpringApplicationRunListener:共 6 个——starting、environmentPrepared、contextPrepared、contextLoaded、started、ready

addListeners 与 spring.factories 能收到全部;@Component 的监听器只收到 refresh 之后的 6 个。

    本文用到的工具与边界

    • 本机 macOS 27 arm64 / OpenJDK 21.0.12(Homebrew) / Spring Boot 4.0.8(Spring Framework 7.0.9、Tomcat 11.0.24) / Spring Cloud 2025.1.3;用 javac 编译、java 直接运行,依赖由 Maven 从 Maven Central 解析;数字每次运行会有小幅抖动。用 Spring Boot 4.0.8 的单个程序(第一至三节用 spring-boot-starter,非 Web 模式;第四节用 spring-boot-starter-webmvc,内嵌 Tomcat),每个场景一个独立 JVM;时间是从 main() 第一行起算的毫秒数,单次运行,每次会有抖动;Bean 定义数取自 getBeanDefinitionCount();第四节的外部客户端是另一个 Python 进程,用 5 ms 间隔轮询端口,所以「第一次连上」的时间有几毫秒的误差
