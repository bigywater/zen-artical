CORS:预检请求与配置的三个位置

浏览器报 CORS 错误,服务端到底返回了什么?预检请求和真正的请求分别带哪些头?@CrossOrigin、addCorsMappings、CorsFilter 三个位置有什么区别?为什么 500 和 404 在浏览器里总是变成 CORS 错误?这篇在 Spring Boot 4.0.8 上用手工带 Origin 的请求逐个看响应头。

403
不在白名单的来源,实际请求和预检请求都被拒绝,方法不执行
1800
没写 maxAge 时预检响应的默认 Access-Control-Max-Age(秒)
0
没有匹配 CORS 配置的路径上,500 和 404 响应里的 CORS 头个数

无配置

实测 · 本机执行输出 
  GET /plain  [Origin: https://a.example] → 200  body='plain'
      CORS 响应头:(没有)
  GET /plain  [] → 200  body='plain'
      CORS 响应头:(没有)
  OPTIONS /plain  [Origin: https://a.example Req-Method: GET] → 200  body=''
      CORS 响应头:(没有)

服务端照常返回,拦住读取的是浏览器;CORS 不是访问控制。

      CORS 响应头:{'Vary': ['Origin', 'Access-Control-Request-Method', 'Access-Control-Request-Headers']}

      CORS 响应头:{'Vary': ['Origin', 'Access-Control-Request-Method', 'Access-Control-Request-Headers'], 'Allow-Origin': 'https://a.example', 'Allow-Methods': 'GET', 'Max-Age': '1800'}
  OPTIONS /ann  [Origin: https://evil.example Req-Method: GET] → 403  body='Invalid CORS request'
      CORS 响应头:{'Vary': ['Origin', 'Access-Control-Request-Method', 'Access-Control-Request-Headers']}

白名单外的来源 403;预检与实际请求带的头不同;同源不算跨域。
