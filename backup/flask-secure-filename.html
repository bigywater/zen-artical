safe_join

实测 · 本机执行输出 
  safe_join(上传目录, 'a.txt'         ) → '<uploads>/a.txt'
  safe_join(上传目录, 'sub/a.txt'     ) → '<uploads>/sub/a.txt'
  safe_join(上传目录, '../x'          ) → None
  safe_join(上传目录, '/etc/passwd'   ) → None
  safe_join(上传目录, 'sub/../../x'   ) → None
  safe_join(上传目录, 'a/../a.txt'    ) → '<uploads>/a.txt'
  safe_join(上传目录, ''              ) → '<uploads>'

    本文用到的工具与边界

    • 本机 macOS 27 arm64 / Python 3.14.7 / Flask 3.1.3 / Werkzeug 3.1.9 / Jinja2 3.1.6 / SQLAlchemy 2.1.1 / gunicorn 26.2.0(都装在自己的虚拟环境里);大多数实验用 Flask 的 test_client(直接调用 WSGI 应用,不经过网络),需要真实 HTTP 时另起 gunicorn 或开发服务器(端口 9600 以上,本机 127.0.0.1);计时用 time.perf_counter,数字每次运行会有小幅抖动。实验在 macOS 上运行,Windows 保留名的处理依赖 os.name,没有在 Windows 上验证
    • 没有验证:Windows 上 secure_filename 对 CON、NUL 等保留名的处理、符号链接导致的逃逸(上传目录里存在指向外部的链接)、文件系统大小写与 Unicode 规范化造成的同名冲突、磁盘配额
