@Query 与分页:count 查询与排序的坑

Page 和 Slice 差在哪?count 查询什么时候会省掉?原生查询的排序为什么报 Unknown column?翻页翻着翻着为什么重复了?深分页怎么这么慢?join fetch 加 Pageable 会怎样?这篇在 Spring Boot 4.0.8、Hibernate 7、MySQL 的 50 万行表上逐个实测。

896 / 1000
按只有 10 个取值的列排序翻 50 页,读到 1000 行但只有 896 个不同的行
91.7 ms vs 0.7 ms
offset 499980 的 Slice 与 keyset(id > 499980)的耗时
20000 vs 50
join fetch 加分页时,没写 countQuery 的总数与写了之后的总数

Page、Slice、List

实测 · 本机执行输出 
findByStatus("NEW", PageRequest.of(0, 20))(Page)  ⇒ Page(第 0 页,内容 20 行,总数 125000,总页数 6250),用时 114 ms,发出 2 条 SQL
    select … from ord o1_0 where o1_0.status=? limit ?
    select count(o1_0.id) from ord o1_0 where o1_0.status=?
findSliceByStatus("NEW", PageRequest.of(0, 20))(Slice)  ⇒ Slice(内容 20 行,hasNext=true),用时 5 ms,发出 1 条 SQL
    select … from ord o1_0 where o1_0.status=? limit ?
findListByStatus("NEW", PageRequest.of(0, 20))(List)  ⇒ 20 行,用时 5 ms,发出 1 条 SQL
    select … from ord o1_0 where o1_0.status=? limit ?
@Query("select o from Ord o where o.status = ?1") Page,不写 countQuery  ⇒ Page(第 0 页,内容 20 行,总数 125000,总页数 6250),用时 24 ms,发出 2 条 SQL
    select … from ord o1_0 where o1_0.status=? limit ?
    select count(o1_0.id) from ord o1_0 where o1_0.status=?
@Query(…, countQuery = …) Page  ⇒ Page(第 0 页,内容 20 行,总数 125000,总页数 6250),用时 23 ms,发出 2 条 SQL
    select … from ord o1_0 where o1_0.status=? limit ?
    select count(o1_0.id) from ord o1_0 where o1_0.status=?

Page 两条 SQL(数据加 count),Slice 与 List 一条;@Query 的 count 会自动推出来。

省掉 count

实测 · 本机执行输出 
findByIdLessThanEqual(5, 第 0 页,每页 20)(总共只有 5 行)  ⇒ Page(第 0 页,内容 5 行,总数 5,总页数 1),用时 4 ms,发出 1 条 SQL
    select … from ord o1_0 where o1_0.id<=? limit ?
findByIdLessThanEqual(30, 第 0 页,每页 20)(总共 30 行,第一页满了)  ⇒ Page(第 0 页,内容 20 行,总数 30,总页数 2),用时 4 ms,发出 2 条 SQL
    select … from ord o1_0 where o1_0.id<=? limit ?
    select count(o1_0.id) from ord o1_0 where o1_0.id<=?
findByIdLessThanEqual(30, 第 1 页,每页 20)(最后一页只有 10 行)  ⇒ Page(第 1 页,内容 10 行,总数 30,总页数 2),用时 3 ms,发出 1 条 SQL
    select … from ord o1_0 where o1_0.id<=? limit ?,?
findByIdLessThanEqual(30, 第 5 页,每页 20)(超出末页)  ⇒ Page(第 5 页,内容 0 行,总数 30,总页数 2),用时 1 ms,发出 2 条 SQL
    select … from ord o1_0 where o1_0.id<=? limit ?,?
    select count(o1_0.id) from ord o1_0 where o1_0.id<=?

内容不足一页(且非空)时,Page 靠 offset 加内容行数算出总数,不发 count。

原生查询 Sort.by("created_at")(列名)  ⇒ Page(第 0 页,内容 3 行,总数 125000,总页数 41667),用时 122 ms,发出 2 条 SQL
    select … from ord where status = ? order by created_at asc limit ?

    select … from ord where status = ? limit ?

  分页遍历前 1000 行(每页 20,50 页)按 bucket: ASC:共读到 1000 行,其中不同的行 896 个
  分页遍历前 1000 行(每页 20,50 页)按 bucket: ASC,id: ASC:共读到 1000 行,其中不同的行 1000 个

原生查询的 Sort 要写列名;排序列不唯一会让翻页重复和漏行,要补上唯一列。

深分页

实测 · 本机执行输出 
  第 0 页(offset 0):Slice 0.6 ms;Page(多一条 count(*))43.6 ms
  第 1000 页(offset 20000):Slice 4.7 ms;Page(多一条 count(*))47.8 ms
  第 12500 页(offset 250000):Slice 45.1 ms;Page(多一条 count(*))87.6 ms
  第 24999 页(offset 499980):Slice 91.7 ms;Page(多一条 count(*))132.2 ms
  keyset:where id > 0 order by id limit 20:0.9 ms
  keyset:where id > 20000 order by id limit 20:0.7 ms
  keyset:where id > 250000 order by id limit 20:0.6 ms
  keyset:where id > 499980 order by id limit 20:0.7 ms

offset 越大越慢;keyset 的耗时与位置无关,但只能翻下一页。

join fetch 加分页

实测 · 本机执行输出 
@Query("select c from Customer c join fetch c.orders") Page,每页 5 个 customer  ⇒ Page(第 0 页,内容 5 行,总数 20000,总页数 4000),用时 127 ms,发出 2 条 SQL
    select … from customer c1_0 join ord o1_0 on c1_0.id=o1_0.customer_id
    select count(c1_0.id) from customer c1_0 join ord o1_0 on c1_0.id=o1_0.customer_id
同上,但 countQuery 指向 select count(c) from Customer c  ⇒ Page(第 0 页,内容 5 行,总数 50,总页数 10),用时 98 ms,发出 2 条 SQL
    select … from customer c1_0 join ord o1_0 on c1_0.id=o1_0.customer_id
    select count(c1_0.id) from customer c1_0
  Hibernate 日志(WARN 及以上)共 5 条:
    LOG o.h.t.s.i.ExceptionHandlerLoggedImpl WARN GenerationTarget encountered exception accepting command : Error executing DDL "alter table ord drop foreign key FKluv11f42b6omo6qhhp4alwf1m" via JDBC [Table 'demo.ord' doesn't exist]
    LOG org.hibernate.orm.jdbc.error WARN HHH000247: ErrorCode: 1054, SQLState: 42S22
    LOG org.hibernate.orm.jdbc.error WARN Unknown column 'createdAt' in 'order clause'
    LOG org.hibernate.orm.query WARN HHH90003004: firstResult/maxResults specified with collection fetch; applying in memory

在内存里分页,count 数的是 join 后的行数,要显式写 countQuery。
