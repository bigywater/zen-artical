commit-graph:git log 为什么变快

git log 在大仓库里为什么能这么快?关键是 commit-graph:把所有提交的 parent、tree、时间和世代数放进一个紧凑的文件。这篇在 3 万个提交的历史上测前后耗时,再按字节解析这个文件,看每条记录里存了什么。

5.0 ~ 8.5 倍
30,300 个提交上,四个常见命令写入 commit-graph 之后的加速比
36 字节
CDAT 块里每个提交的记录:tree、两个 parent 下标、世代数与时间
1.8 MB
30,300 个提交的 commit-graph 文件大小

没有 commit-graph

实测 · 本机执行输出 
  $ git rev-list --count HEAD; git rev-list --merges --count HEAD; ls .git/objects/info 2>&1
  30300
  300

遍历历史时 git 要从对象库里逐个读出 commit 对象、解压、解析 parent 行。3 万个提交的历史上,一次 rev-list --count 就要约 100 ms。

文件结构

实测 · 本机执行输出 
  数全部提交                            99.0 ms
  log --topo-order -1              98.1 ms
  is-ancestor(25000 步之前)           82.0 ms
  merge-base                       67.7 ms

.git/objects/info/commit-graph 以 8 字节头(签名 CGPH、版本、哈希版本、块数、基础图数)开头,然后是块表。OIDF 与 OIDL 是提交 hash 的 fanout 和升序表,CDAT 每个提交 36 字节,GDA2 是修正世代数(提交时间的偏移)。

一条记录

实测 · 本机执行输出 
  $ git commit-graph write --reachable; ls -l .git/objects/info/commit-graph | awk '{print $5, $9}'
  1819112 .git/objects/info/commit-graph
  签名 b'CGPH'  版本 1  哈希版本 1  块数 4  基础图数 0
  0000  43 47 50 48 01 01 04 00 4f 49 44 46 00 00 00 00  CGPH....OIDF....
  …(共 1819112 字节)
  块 OIDF  偏移       68  长度     1024
  块 OIDL  偏移     1092  长度   606000
  块 CDAT  偏移   607092  长度  1090800
  块 GDA2  偏移  1697892  长度   121200
  OIDF 末项 = 30,300 个提交(= git rev-list --all --count: 30300)

根 tree 的 hash、第一个 parent 和第二个 parent 的下标(指向 OIDL,不重复存 hash),以及合并在一起的世代数和提交时间。没有第二个 parent 时用占位值 0x70000000。多于两个 parent 的章鱼合并走另一个 EDGE 块(本例没有)。

世代数

实测 · 本机执行输出 
  HEAD=efe5e65458…  下标 28418
  tree   9c3de550eb…(git 里是 9c3de550eb…)
  parent1 下标 11019 → 5c5c393a24…(git: 5c5c393a24…)
  parent2 下标 16529 → 8b7a5ffb26…(git: 8b7a5ffb26…)  HEAD 是合并提交
  对一个普通提交(HEAD^1~1)取 parent2 字段: 0x70000000(没有第二个 parent 时的占位值)
  提交时间 1767291900(git: 1767291900);世代数 30300
  世代数范围 1 ~ 30300;根提交的世代数 = 1

世代数是“比所有 parent 的最大世代数大 1”,根提交为 1。判断 A 是不是 B 的祖先时,如果 A 的世代数不比 B 小,就可以立刻判定不是,不必一路走到根。

快多少

实测 · 本机执行输出 
  数全部提交                            99.0 →     15.3 ms   快 6.5 倍
  log --topo-order -1              98.1 →     11.6 ms   快 8.5 倍
  is-ancestor(25000 步之前)           82.0 →     14.5 ms   快 5.6 倍
  merge-base                       67.7 →     13.6 ms   快 5.0 倍

本例四个命令都快了 5.0~8.5 倍,剩下的 11~15 ms 大部分是进程启动。git gc 默认会写 commit-graph,也可以手动 git commit-graph write --reachable。

自动写

实测 · 本机执行输出 
  $ ls .git/objects/info/; git gc -q; ls .git/objects/info/
  commit-graph
  packs
  $ git config gc.writeCommitGraph || echo "gc.writeCommitGraph 未显式设置(默认 true)"
  gc.writeCommitGraph 未显式设置(默认 true)

新仓库 git gc 之后目录里就有 commit-graph,说明 gc.writeCommitGraph 默认开启。
