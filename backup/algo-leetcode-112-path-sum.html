LeetCode 112. 路径总和

给定一棵二叉树和一个目标和，判断是否存在一条从根到叶子的路径，路径上所有结点值加起来恰好等于目标和。一个常见陷阱是：判断条件只写了"累计和等于目标值就返回真"，没有同时要求"当前结点必须是叶子"——这样如果累计和在某个中间结点就恰好凑够了，会被提前误判为找到答案，即使这个结点后面还有子树。本文用真实反例和刻意针对性设计的随机测试验证这个错误，给出正确写法、5 种语言实现，以及回溯探索的分步演示。

陷阱：累计和等于目标值就返回真，忘了必须走到叶子

题目要求的是"根到叶子"的路径，但一个很容易漏看的地方是：判断条件只写了"当前累计和等于目标值就返回真"，没有同时要求"当前结点必须是叶子"。这样一旦从根往下走的过程中，累计和在某个中间结点恰好凑够了目标值，就会被提前误判为找到了一条合法路径，即使这个结点后面还有子树、根本不是终点：

真实实测 · 本机执行输出
构造的树：根 5 → 左孩子 5（还有子结点 100，不是叶子）\ntarget=5\n正确写法（必须走到叶子才能判断）  →  false\n陷阱写法（累计和等于target就返回真） →  true

陷阱写法在根到左孩子这一步，累计和恰好是 5+... 不对，这里更准确地说是：陷阱写法一开始就判断"当前结点的值等于 target 就返回 true"（这里是根结点 5 本身等于 target=5），完全没有检查根是不是叶子——根其实还有孩子 5，不是路径的终点。为了确认这不是个例，做了一次针对性的随机测试：故意把 target 设成"根到某个内部结点"的路径和（最容易触发陷阱）：

超过一半的情况会踩坑——因为随机选的 target 有很高概率恰好对应某个内部结点的累计和，陷阱写法看到"和已经凑够了"就提前返回真，完全不检查这条路径是否真的走到了叶子。"必须是叶子"这个约束是题目定义的核心部分，不能只看数字凑没凑够。

递归 + 剩余目标值传递：五种语言的实现

hasPathSum(root, target)：空树直接返回假；只有走到叶子结点时，才拿"剩余目标值"跟叶子的值比较；否则把剩余目标值减去当前结点的值，分别递归左右子树，只要有一侧能找到就返回真。时间 O(n)，空间是递归深度 O(h)。Python、Java、Go、JavaScript、C++ 都是真实编译运行的，用同一组 5 个测试用例。

Python · 解法代码def has_path_sum(root, target): if root is None: return False if root.left is None and root.right is None: # 必须是叶子才能算一条完整路径 return root.val == target remain = target - root.val return has_path_sum(root.left, remain) or has_path_sum(root.right, remain)

Java · 解法代码class Solution { public boolean hasPathSum(TreeNode root, int targetSum) { if (root == null) return false; if (root.left == null && root.right == null) return root.val == targetSum; // 必须是叶子 int remain = targetSum - root.val; return hasPathSum(root.left, remain) || hasPathSum(root.right, remain); } }
