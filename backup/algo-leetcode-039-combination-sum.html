LeetCode 39. 组合总和

给定一组互不相同的正整数候选数和一个目标值，找出所有和等于目标的组合，同一个数字可以无限次使用，组合不同的判定是"某个数字使用的次数不同"（[2, 3] 和 [3, 2] 是同一个组合）。做法是回溯，关键有两个细节：递归时下一层仍从当前下标开始（因为允许重复使用），且不回头选前面的数（避免同一个组合被排列成多种顺序）。本文用真实数据展示"每层都从头选"会得到多少重复的排列，实测两种做法的耗时，给出五种语言的实现，并把递归的过程做成分步演示。

题意与示例

完整题目见官方页面（链接在文末）。组合之间、组合内部的顺序都不作要求，核对时先把每个组合内部排序，再把所有组合排序后比较。基准解依次决定"第 i 个候选数用几次"，是与"边走边选"的回溯完全不同的写法。一共 12 组用例，覆盖：官方示例、目标无法凑出、目标比所有候选都小、候选只有一个、候选大于目标：

陷阱：每层都从头选，会得到同一个组合的所有排列

如果回溯每一层都从第 0 个候选数开始选，那么 [2, 2, 3]、[2, 3, 2]、[3, 2, 2] 会被当作三个不同的答案。下面是这种写法与 solve 的真实结果：

[2, 3, 6, 7], 7 每层从头选的具体结果：[[2, 2, 3], [2, 3, 2], [3, 2, 2], [7]]

[2, 3, 6, 7] 目标 7：每层从头选得到 4 个（[2, 2, 3] 的三种排列加上 [7]），正确答案只有 2 个组合。候选数越多，重复越严重：[2, 3, 5, 7] 目标 12，每层从头选得到 35 个，正确答案只有 7 个。解决办法是递归时传入下标 start，只允许选下标不小于 start 的数，这样每个组合只会以不降序的顺序出现一次。

回溯：五种语言的实现

先把候选数排序。dfs(start, remain) 表示还需要凑 remain，可以选下标不小于 start 的候选数。remain 为 0 时收集当前路径；否则从 start 开始依次尝试候选数 x：如果 x 大于 remain，由于已排序，后面的更大，直接结束这一层；否则选它，递归时传 i（不是 i + 1，因为可以重复使用），返回后撤销。Python、Java、Go、JavaScript、C++ 都是真实编译运行的。

Python · 解法代码def solve(candidates, target): candidates = sorted(candidates) # 排序之后，一旦某个数超过剩余的目标，后面的更大，可以直接停 res, path = [], [] def dfs(start, remain): if remain == 0: res.append(list(path)) return for i in range(start, len(candidates)): # 只往后选（i 从 start 开始），保证组合里数字不降序，不会出现 [2,3] 和 [3,2] 重复 x = candidates[i] if x > remain: # 剪枝：已排序，后面的更大 break path.append(x) dfs(i, remain - x) # 传 i 而不是 i+1：同一个数字可以重复使用 path.pop() dfs(0, target) return res

Java · 解法代码class Solution { public List<List<Integer>> combinationSum(int[] candidates, int target) { Arrays.sort(candidates); // 排序之后，一旦某个数超过剩余的目标，后面的更大，可以直接停 List<List<Integer>> res = new ArrayList<>(); dfs(candidates, 0, target, new ArrayList<>(), res); return res; } private void dfs(int[] cs, int start, int remain, List<Integer> path, List<List<Integer>> res) { if (remain == 0) { res.add(new ArrayList<>(path)); return; } for (int i = start; i < cs.length; i++) { // 只往后选，保证组合里数字不降序，不会出现 [2,3] 和 [3,2] 重复 if (cs[i] > remain) break; // 剪枝：已排序，后面的更大 path.add(cs[i]); dfs(cs, i, remain - cs[i], path, res); // 传 i 而不是 i+1：同一个数字可以重复使用 path.remove(path.size() - 1); } } }

耗时实测

候选数固定为 [2, 3, 5, 7]，目标从 20 增大到 80，每个规模取三次中最快的一次，基准解不做排序剪枝：

真实实测 · 本机执行输出
target | 暴力解 | 本文解法
        20 |     0.051 ms | 0.019 ms
        40 |     0.331 ms | 0.143 ms
        60 |     1.182 ms | 0.542 ms
        80 |      （未测，太慢） | 1.472 ms

排序加剪枝的回溯比基准快约 2 到 3 倍（例如目标 60 时 0.54ms 对 1.18ms），二者都随目标的增大而快速增长，因为组合个数本身在快速增长。基准解在目标 80 时没有再测。这里的差距只反映"剪枝省掉了一些没有意义的尝试"，不能说明复杂度上有本质的不同：结果个数决定了下界。
