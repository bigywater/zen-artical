X.509 证书与信任链:怎样验证一张证书

TLS 的安全最终落在一张证书上:你怎么知道对面真的是 example.com?这篇取下 example.com 的证书链,看每一张证书的字段和扩展,亲自用上一级公钥验证每个签名,找到它在信任库里的根,再用几个故意配错的站点看各种验证失败,最后看 SNI 与主机名验证怎么配合。

验证签名

实测 · 本机执行输出 
  [0] 用 [1] 的公钥验证签名:True
  [1] 用 [2] 的公钥验证签名:True
  [2] 用 [3] 的公钥验证签名:True
  链的最后一张 [3]:主体 == 签发者?True(= 自签名根)
  本机 Python 的信任库里有 192 张根 / 受信 CA 证书
  链的最后一张的签发者 "C=US, O=SSL Corporation, CN=SSL.com TLS ECC Root CA 2022" 在信任库里:找到 1 张同名的;用它验证最后一张的签名:True
  信任库里 EC 根 60 张,RSA 根 132 张;最早到期的 2026-11-27,最晚到期的 2054-12-09

每张证书用上一级公钥验签;根在信任库里找到并验签通过。

验证失败

实测 · 本机执行输出 
  expired.badssl.com          (证书过期):验证失败 错误码 10:certificate has expired
  wrong.host.badssl.com       (证书是给别的主机名签的):验证失败 错误码 62:Hostname mismatch, certificate is not valid for 'wrong.host.badssl.com'.
  self-signed.badssl.com      (自签名证书):验证失败 错误码 18:self-signed certificate
  untrusted-root.badssl.com   (根不在信任库里):验证失败 错误码 19:self-signed certificate in certificate chain
  revoked.badssl.com          (证书已被吊销):握手成功(TLSv1.2)——没有报错
  注意 revoked.badssl.com:证书其实已被吊销,Python 的默认设置却让握手成功——默认不检查吊销(CRL / OCSP),这是常见的盲区

过期 10、主机名 62、自签名 18、未知根 19;吊销默认不检查。

SNI 与主机名

实测 · 本机执行输出 
  SNI = example.com           → 默认验证:通过;不验证时服务器给的证书 SAN:['example.com', '*.example.com']
  SNI = www.example.com       → 默认验证:通过;不验证时服务器给的证书 SAN:['example.com', '*.example.com']
  SNI = example.org           → 默认验证:通过;不验证时服务器给的证书 SAN:['example.org', '*.example.org']
  SNI = totally-wrong.invalid → 默认验证:握手失败:SSLError [SSL: SSLV3_ALERT_HANDSHAKE_FAILURE] ssl/tls alert handshake;不验证时服务器给的证书 SAN:握手失败:SSLError [SSL: SSLV3_ALERT_HANDSHAKE_FAILURE] ssl/tls alert handshake
  完全不发 SNI:握手失败 SSLError [SSL: SSLV3_ALERT_HANDSHAKE_FAILURE] ssl/tls alert handshake
  验证由两部分组成:(1)证书链到受信任的根;(2)证书的 SAN 里有我要连的名字(通配符 *.example.com 匹配 www.example.com)。关掉第二项(check_hostname=False)只会得到“链是好的”,而不知道是不是对的站点

SNI 决定给哪张证书,SAN 里要有要连的名字;不认识的 SNI 直接 handshake_failure。
