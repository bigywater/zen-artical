错误详情:google.rpc.Status 与 details

gRPC 的状态码只有 17 个,业务上要告诉客户端“哪个字段错了”“多久后再试”怎么办?答案是 google.rpc.Status 的 details。这篇看它在线上长什么样、能带多大、跨服务时会不会丢。

3 个头
trailers 里 grpc-status、grpc-message、grpc-status-details-bin
1 MiB 可以 / 20 MiB 不行
details 太大时客户端的表现(COMPRESSION_ERROR)
code、details 保留
A 用 fmt.Errorf("%w") 包装 B 的错误后客户端看到的

google.rpc.Status(code、message、details 列表)被序列化后放在 trailer grpc-status-details-bin 里,与 grpc-status、grpc-message 并存。

  20480 KiB:code=Unavailable details=0 message="error reading from server: connection error: COMPRESSION_ERROR";线上 trailers []

details 在 trailers 里,受头部大小限制(客户端默认约 16 MiB);1 MiB 以内正常,20 MiB 连接出错。不要放大块数据。

边界情况

实测 · 本机执行输出 
  status.New(codes.OK).WithDetails 返回的错误:no error details for status with code OK
  客户端:code=NotFound message="找不到";Details() 个数 1
      不认识的类型得到的是 error:proto: not found
      线上 trailers:[grpc-status: 5 grpc-message: %E6%89%BE%E4%B8%8D%E5%88%B0 grpc-status-details-bin: CAUSCeaJvuS4jeWIsBolCh50eXBlLmdvb2d…(共 95 字符)]

OK 状态不能带 details;客户端不认识的类型在 Details() 里以 error 的形式出现。

跨服务透传

实测 · 本机执行输出 
  直接 return err                  → 客户端 code=FailedPrecondition message="B 的错误" details 里的 reason [FROM_B]
  status.Convert(err).Err()      → 客户端 code=FailedPrecondition message="B 的错误" details 里的 reason [FROM_B]
  fmt.Errorf("A: %w", err)       → 客户端 code=FailedPrecondition message="A: rpc error: code = FailedPrecondition desc = B 的错误" details 里的 reason [FROM_B]

直接返回下游的错误,details 会原样传给上游客户端;用 %w 包装也保留 code 和 details,但 message 会变成整句错误文本。
