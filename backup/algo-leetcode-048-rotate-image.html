LeetCode 48. 旋转图像

给定一个 n × n 的二维矩阵，把它原地顺时针旋转 90 度，不允许另外开一个二维数组。最直接的想法是找出每个位置旋转后的落点，但落点的对应关系（(i, j) 到 (j, n-1-i)）很容易写错。更简洁的做法是把旋转拆成两次翻转：先沿主对角线转置，再把每一行左右翻转。本文用真实数据展示只做转置会得到什么，验证另一种"四个位置循环交换"的原地做法与它结果一致并比较耗时，给出五种语言的实现，并把两步做成分步演示。

几种做法的对比

下面在同一个矩阵上对比：只做转置（不翻转）、solve（转置加翻转）、四个位置循环交换。并验证：连续旋转 4 次是否回到原样；随机 3000 个方阵上两种原地做法是否一致；以及各自的耗时：

n= 200: 转置+翻转     0.59 ms    四位置循环     1.25 ms

只做转置得到的是沿主对角线的镜像 [[1, 4, 7], [2, 5, 8], [3, 6, 9]]，不是旋转，需要再把每行翻转才是顺时针旋转 90° 的结果 [[7, 4, 1], [8, 5, 2], [9, 6, 3]]。四个位置循环交换的做法：每次把 (i, j)、(j, n-1-i)、(n-1-i, n-1-j)、(n-1-j, i) 这四个位置循环换一遍，只遍历矩阵的四分之一，但在 Python 里每次要做四元组的赋值，实测比"转置加翻转"慢（n = 800 时 37.2ms 对 12.9ms，约 2.9 倍）。随机 3000 个方阵上两种做法结果一致，连续旋转 4 次也确实回到了原样。

转置加翻转：五种语言的实现

转置：对每个 i 和 j > i，交换 matrix[i][j] 和 matrix[j][i]。翻转：每一行原地左右翻转。顺时针旋转 90° 等价于这两步的组合。Python、Java、Go、JavaScript、C++ 都是真实编译运行的；Java、Go、JavaScript、C++ 都是真正原地修改，不额外分配矩阵。

Python · 解法代码def solve(matrix): n = len(matrix) for i in range(n): # 第一步：沿主对角线转置 for j in range(i + 1, n): matrix[i][j], matrix[j][i] = matrix[j][i], matrix[i][j] for row in matrix: # 第二步：每一行左右翻转 row.reverse() return matrix

Java · 解法代码class Solution { public void rotate(int[][] matrix) { int n = matrix.length; for (int i = 0; i < n; i++) { // 第一步：沿主对角线转置 for (int j = i + 1; j < n; j++) { int t = matrix[i][j]; matrix[i][j] = matrix[j][i]; matrix[j][i] = t; } } for (int[] row : matrix) { // 第二步：每一行左右翻转 for (int l = 0, r = n - 1; l < r; l++, r--) { int t = row[l]; row[l] = row[r]; row[r] = t; } } } }

复杂度实测

边长 n 分别为 100、200、400、800（元素个数是 n²），每个规模取三次中最快的一次，基准解是 zip 版本（会新建一个矩阵）：

真实实测 · 本机执行输出
边长 n | 暴力解 | 本文解法
       100 |     0.063 ms | 0.148 ms
       200 |     0.591 ms | 0.606 ms
       400 |     1.718 ms | 2.946 ms
       800 |     9.717 ms | 12.701 ms

两种做法都是 O(n²)，边长每翻一倍，理论上耗时增长 4 倍：原地版本实测 4.1 倍、4.9 倍、4.3 倍，比较接近；zip 版本 9.4 倍、2.9 倍、5.7 倍，波动比较大，小规模上计时的噪声占比更高。这里 zip 版本（C 层循环）与原地版本（Python 层循环）耗时接近，并不能说明原地更慢或更快，原地的价值是不需要额外的 O(n²) 空间，这里没有测量内存。
