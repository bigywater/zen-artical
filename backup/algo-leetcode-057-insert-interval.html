LeetCode 57. 插入区间

给定一个已经按起点排好序、互不重叠的区间列表，再插入一个新区间，必要时合并，返回仍然有序且互不重叠的列表。因为原列表已经有序，不需要重新排序，一遍扫描就够：先把完全在新区间左边的区间原样保留；再把与新区间有重叠的全部合并进新区间；最后把完全在新区间右边的原样保留。本文用真实数据展示一个很容易漏掉的边界（新区间放在哪里），实测线性扫描与"放进去再重新合并"的耗时，给出五种语言的实现，并把三段式扫描做成分步演示。

陷阱：合并之后的新区间要"无条件放进去"

三段式扫描里，合并完成后必须把（合并后的）新区间放进结果，不管它有没有与任何区间重叠。一个容易写错的做法是：只在遇到第一个"在新区间右边的区间"时才顺手插入新区间。这样当新区间在所有区间的最右边，或者被别的区间完全包含、或者原列表为空时，新区间会丢掉。下面是这种写法的真实结果：

真实实测 · 本机执行输出
# 只在遇到「右边的区间」时才插入新区间的写法
[[1, 3], [6, 9]] + [2, 5]: 该写法 -> [[1, 5], [6, 9]]    solve -> [[1, 5], [6, 9]]
[[1, 5]] + [6, 8]: 该写法 -> [[1, 5]]    solve -> [[1, 5], [6, 8]]
[[1, 5]] + [2, 3]: 该写法 -> []    solve -> [[1, 5]]
[] + [5, 7]: 该写法 -> []    solve -> [[5, 7]]
[[3, 5], [12, 15]] + [6, 6]: 该写法 -> [[3, 5], [6, 6], [12, 15]]    solve -> [[3, 5], [6, 6], [12, 15]]

[[1, 5]] + [6, 8]：新区间在最右边，那个写法得到 [[1, 5]]，[6, 8] 丢了；[[1, 5]] + [2, 3] 与 [] + [5, 7] 更糟，得到的是空列表，原来的区间也一起消失了（合并进新区间之后没有被重新放回）。第一组和最后一组两个写法碰巧相同，是因为那时新区间的右边刚好还有区间，能触发插入。所以这个错误在新区间位于最右边或者列表为空时暴露。

三段式扫描：五种语言的实现

i 是扫描位置，[s, e] 是当前的新区间。第一段：intervals[i][1] < s（终点小于新区间起点）的区间完全在左边，原样加入结果。第二段：intervals[i][0] <= e（起点不超过新区间终点）的区间与新区间重叠，把 s 取成两个起点里较小的，e 取成两个终点里较大的。第二段结束后把 [s, e] 加入结果。第三段：剩下的区间完全在右边，原样加入。Python、Java、Go、JavaScript、C++ 都是真实编译运行的。

Python · 解法代码def solve(intervals, new_interval): res = [] i, n = 0, len(intervals) s, e = new_interval while i < n and intervals[i][1] < s: # 1) 完全在新区间左边（终点 < 新区间起点）的，原样保留 res.append(intervals[i]) i += 1 while i < n and intervals[i][0] <= e: # 2) 与新区间有重叠的，全部合并进新区间 s = min(s, intervals[i][0]) e = max(e, intervals[i][1]) i += 1 res.append([s, e]) # 合并后的新区间（即使一个都没重叠，也要放进去） while i < n: # 3) 完全在新区间右边的，原样保留 res.append(intervals[i]) i += 1 return res

Java · 解法代码class Solution { public int[][] insert(int[][] intervals, int[] newInterval) { List<int[]> res = new ArrayList<>(); int i = 0, n = intervals.length; int s = newInterval[0], e = newInterval[1]; while (i < n && intervals[i][1] < s) res.add(intervals[i++]); // 1) 完全在新区间左边的，原样保留 while (i < n && intervals[i][0] <= e) { // 2) 与新区间有重叠的，全部合并进新区间 s = Math.min(s, intervals[i][0]); e = Math.max(e, intervals[i][1]); i++; } res.add(new int[]{s, e}); // 合并后的新区间（即使一个都没重叠，也要放进去） while (i < n) res.add(intervals[i++]); // 3) 完全在新区间右边的，原样保留 return res.toArray(new int[0][]); } }

Go · 解法代码func insert(intervals [][]int, newInterval []int) [][]int { res := [][]int{} i, n := 0, len(intervals) s, e := newInterval[0], newInterval[1] for i < n && intervals[i][1] < s { // 1) 完全在新区间左边的，原样保留 res = append(res, intervals[i]) i++ } for i < n && intervals[i][0] <= e { // 2) 与新区间有重叠的，全部合并进新区间 if intervals[i][0] < s { s = intervals[i][0] } if intervals[i][1] > e { e = intervals[i][1] } i++ } res = append(res, []int{s, e}) // 合并后的新区间（即使一个都没重叠，也要放进去） for i < n { // 3) 完全在新区间右边的，原样保留 res = append(res, intervals[i]) i++ } return res }

耗时实测

已有区间个数 n 分别为 1000、1 万、10 万、100 万，新区间落在最右边（不与任何区间重叠，这样三段式要扫描完整个列表），每个规模取三次中最快的一次：

真实实测 · 本机执行输出
已有区间个数 n | 暴力解 | 本文解法
      1000 |     0.152 ms | 0.054 ms
     10000 |     1.961 ms | 0.461 ms
    100000 |    35.249 ms | 4.868 ms
   1000000 |   581.451 ms | 52.179 ms

本文解法是线性的：从 10 万到 100 万（10 倍）增长约 10.7 倍。基准（放进去、排序、重新合并）也是接近线性，因为 Python 的排序会识别已经有序的输入；100 万时基准 581.5ms，三段式 52.2ms，约 11 倍，差异主要来自基准要多做一次排序和重新合并。
