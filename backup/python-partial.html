做的事：真实对一个partial对象再套一层partial

代码def greet(greeting, name, punctuation="."): return f"{greeting}, {name}{punctuation}" hello = functools.partial(greet, "Hello") hello_excited = functools.partial(hello, punctuation="!") print(hello_excited("Universe")) print(hello_excited.func) # 是hello，还是最原始的greet？ print(hello_excited.args) print(hello_excited.keywords)

验证：partial对象真实是一个有.func/.args/.keywords属性的普通对象，不是闭包

实测 · 本机执行输出 
type(hello)          → <class 'functools.partial'>
hello.func           → <function greet at 0x...>
hello.args           → ('Hello',)
hello.keywords       → {}

这是本文认为functools.partial跟"手写一个闭包函数做同样的事"最真实的区别：partial(greet, "Hello")返回的不是一个普通的函数对象，而是一个真实携带内部状态的functools.partial类型实例，.func、.args、.keywords这几个属性真实把"预先绑定了哪个函数、绑定了哪些位置参数、绑定了哪些关键字参数"这些信息完全暴露出来，可以在运行时被真实检查和内省——如果换成手写def hello(name): return greet("Hello", name)这样一个闭包，外部代码就真实没有任何标准方式能反过来问"这个函数底层包的是哪个原始函数、绑定了什么参数"。

验证：partial套partial，真实不会嵌套，会在构造时展平合并到最底层的原始函数

实测 · 本机执行输出 
hello_excited("Universe")   → "Hello, Universe!"    ← 正常工作

hello_excited.func          → <function greet at 0x...>    ← 真实是最原始的greet，不是hello！
hello_excited.args          → ('Hello',)                     ← 真实是从hello那一层继承下来的位置参数
hello_excited.keywords      → {'punctuation': '!'}           ← 真实只有这一层新加的关键字参数
这是本文认为整篇最反直觉、也最值得记住的真实实现细节：直觉上partial(hello, punctuation="!")应该是"包了一层hello"，hello_excited.func应该指向hello这个partial对象本身；但真实检查下来，hello_excited.func指向的是最原始的greet函数——functools.partial的构造函数真实检测到传进来的hello本身也是一个partial对象，会真实主动把hello.func（greet）、hello.args（("Hello",)）取出来，跟这一层新传入的参数合并展平进新创建的hello_excited对象里，而不是简单地把hello整个存成.func字段再嵌套调用。这样做真实的好处是调用链条不会随着套的层数增多而变长——不管在这个基础上再包几层partial，调用hello_excited(...)真实始终是直接调用一次greet，不会真实经过hello_excited -> hello -> greet这样一层套一层的真实函数调用栈，这在真实需要频繁组合、多层预绑定参数的场景下，避免了调用栈随包装层数线性增长带来的额外开销。
