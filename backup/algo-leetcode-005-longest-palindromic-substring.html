LeetCode 5. 最长回文子串

给定字符串 s，找出其中最长的回文子串。本文用"中心扩展"：把每个位置当作回文的中心，向两边同时扩展，直到两端字符不等。时间 O(n²)，空间 O(1)，写法简单，不容易出错。真正容易漏掉的是回文中心有两种：奇数长度的中心是一个字符，偶数长度的中心是两个相邻字符之间。本文实测只处理奇数中心会漏掉什么，给出五种语言的实现，并把扩展过程做成分步演示。

陷阱：偶数长度的回文没有单个字符做中心

只用"每个字符当中心"的写法，扩展出来的回文长度一定是奇数。"bb"、"abba" 这样的偶数长度回文没有中心字符，必须再把"相邻两个字符之间"也当作中心。下面是只扩展奇数中心的写法和正确写法的真实结果：

真实实测 · 本机执行输出
# 只处理奇数长度中心（漏掉偶数长度）的写法
"cbbd": 只扩奇数中心 -> "c"   正确写法 -> "bb"
"bb": 只扩奇数中心 -> "b"   正确写法 -> "bb"
"abba": 只扩奇数中心 -> "a"   正确写法 -> "abba"

"cbbd" 的最长回文是 "bb"，只扩展奇数中心的写法得到的是 "c"。题目的第二个官方示例恰好就是这种情况，所以这个错误很容易在提交时才被发现。

中心扩展：五种语言的实现

对每个下标 i，做两次扩展：一次从 (i, i) 开始（奇数长度），一次从 (i, i + 1) 开始（偶数长度）。每次扩展到两端字符不相等或越界为止，然后退回一格得到这个中心的最长回文，和当前最优比较长度。Python、Java、Go、JavaScript、C++ 五种语言都是真实编译运行的；实现里用一个 k 循环（0 是奇数、1 是偶数）合并两种中心。

Python · 解法代码def solve(s): def expand(l, r): # 从中心向两边扩，返回回文的 [l, r] while l >= 0 and r < len(s) and s[l] == s[r]: l -= 1 r += 1 return l + 1, r - 1 best_l, best_r = 0, 0 for i in range(len(s)): for l, r in (expand(i, i), expand(i, i + 1)): # 奇数长度、偶数长度两种中心 if r - l > best_r - best_l: best_l, best_r = l, r return s[best_l:best_r + 1]

Java · 解法代码class Solution { public String longestPalindrome(String s) { int bestL = 0, bestR = 0; for (int i = 0; i < s.length(); i++) { for (int k = 0; k < 2; k++) { // k = 0：奇数长度中心；k = 1：偶数长度中心 int l = i, r = i + k; while (l >= 0 && r < s.length() && s.charAt(l) == s.charAt(r)) { l--; r++; } l++; r--; // 退回到最后一个成功的回文 if (r - l > bestR - bestL) { bestL = l; bestR = r; } } } return s.substring(bestL, bestR + 1); } }

复杂度实测：最坏情况下平方增长

最坏输入是全部字符相同（每个中心都能一路扩到边界）。下表里"暴力解"是枚举所有子串再逐个判断回文，每个规模取三次中最快的一次：

真实实测 · 本机执行输出
字符串长度 n | 暴力解 | 本文解法
       100 |     0.715 ms | 0.220 ms
       300 |     8.526 ms | 2.103 ms
      1000 |      （未测，太慢） | 25.396 ms
      2000 |      （未测，太慢） | 102.819 ms
      4000 |      （未测，太慢） | 413.663 ms

中心扩展从 1000 到 2000 再到 4000（每次翻倍），耗时从 26.2ms 涨到 102.1ms 再涨到 424.0ms，每次增长约 4 倍，符合 O(n²)。暴力解在这个测试里只比中心扩展慢 3 到 4 倍（0.76ms 对 0.21ms、8.3ms 对 2.0ms），远没有理论上 O(n³) 与 O(n²) 差一个数量级的样子，因为暴力解里判断回文用的是 Python 内置的切片和比较，跑在 C 层，常数很小；这个差距不能拿来说明"暴力解只慢几倍"，只说明在这个实现下的常数。更大规模的暴力解耗时太长，没有再测。
