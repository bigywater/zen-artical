SQLXML:在 JDBC 中处理 XML 数据

SQLXML 看起来只是把字符串包一层,但驱动的差别、校验的缺失与解析时的外部实体问题都值得提前知道。这篇用真实数据库逐项验证,并检查从数据库读出来的 XML 在客户端解析时是否安全。

/etc/hosts 被读到
getSource(StreamSource) 交给 JDK 默认 TransformerFactory 后外部实体被解析,输出含本机文件内容(DOM / SAX 来源被驱动保护)
缺
MySQL 上用 SAXResult 写入 sax,读回只有 “sax”
2200N vs 全部接受
PG 的 xml 列拒绝格式错误的 XML,MySQL 的 longtext 列什么都接受

校验:什么会被接受

实测 · 本机执行输出 
  ── PostgreSQL(xml 列)
      格式错误(未闭合标签)            → PSQLException(2200N): ERROR: invalid XML content
      多个根元素                  → 接受;读回 “<a/><b/>”
      空字符串                   → 接受;读回 “”
      纯文本                    → 接受;读回 “hello”
      非法字符                  → PSQLException(2200N): ERROR: invalid XML content
      重复属性                   → PSQLException(2200N): ERROR: invalid XML content
      未声明的实体                 → PSQLException(2200N): ERROR: invalid XML content
      编码声明与实际不符              → 接受;读回 “<a>中</a>”
      带 DOCTYPE 与内部实体        → 接受;读回 “<!DOCTYPE d [<!ENTITY e "EXPANDED">]><d>&e;</d>”
      XML 片段(多个顶层节点)         → 接受;读回 “text <b/> more”
      命名空间前缀未声明              → 接受;读回 “<p:a/>”
  用 ps.setString 直接给 xml 列传字符串(不用 SQLXML):PSQLException(42804): ERROR: column "doc" is of type xml but expression is of type character varying
  用 ps.setObject(1, "<a/>", Types.SQLXML):成功
  用 cast(? as xml) 传字符串:成功
  PG 服务端 xml 类型的 XMLSERIALIZE 与 xpath:{x,y} | <a  b="1" ><c/></a>
  ── MySQL(longtext 列)
      格式错误(未闭合标签)            → 接受;读回 “<a><b></a>”
      多个根元素                  → 接受;读回 “<a/><b/>”
      空字符串                   → 接受;读回 “”
      纯文本                    → 接受;读回 “hello”
      非法字符                  → 接受;读回 “<a></a>”
      重复属性                   → 接受;读回 “<a x="1" x="2"/>”
      未声明的实体                 → 接受;读回 “<a>&nope;</a>”
      编码声明与实际不符              → 接受;读回 “<?xml version="1.0" encoding="ISO-8859-1"?><a>中</a>”
      带 DOCTYPE 与内部实体        → 接受;读回 “<!DOCTYPE d [<!ENTITY e "EXPANDED">]><d>&e;</d>”
      XML 片段(多个顶层节点)         → 接受;读回 “text <b/> more”
      命名空间前缀未声明              → 接受;读回 “<p:a/>”
