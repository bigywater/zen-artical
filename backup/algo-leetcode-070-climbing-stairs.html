LeetCode 70. 爬楼梯

爬 n 阶楼梯到楼顶，每次可以爬 1 或 2 阶，问有多少种不同的方法。到第 n 阶的最后一步，要么是从第 n - 1 阶爬 1 阶，要么是从第 n - 2 阶爬 2 阶，所以方法数 f(n) = f(n-1) + f(n-2)，这就是斐波那契数列（f(0) = f(1) = 1）。这是最经典的动态规划入门题。本文用真实数据展示不带记忆化的递归调用次数如何爆炸，验证一个常见的"用黄金分割公式直接算"的想法在 n 多大时开始出错，用 Java 展示 32 位整数在 n = 46 时溢出，给出五种语言的实现，并把填表做成分步演示。

陷阱一：不带记忆化的递归

最直接的写法是 f(n) = f(n-1) + f(n-2) 直接递归，不记忆。同一个子问题会被重复计算很多次。下面是真实统计的调用次数和耗时：

n=10: 结果       89，调用       177 次，     0.01 ms
n=20: 结果    10946，调用     21891 次，     1.26 ms
n=25: 结果   121393，调用    242785 次，    13.90 ms
n=30: 结果  1346269，调用   2692537 次，   182.93 ms

调用次数几乎正好是结果的 2 倍减 1（n = 10 时 177 = 2 × 89 - 1，n = 33 时 11405773 = 2 × 5702887 - 1）。n 每增加 5，调用次数约乘 11（黄金分割数的 5 次方），耗时也一样：n = 30 时 183ms，n = 33 时 660ms。而迭代只需要 n 次加法。

陷阱二：通项公式在双精度浮点下会出错

斐波那契数列有封闭形式（Binet 公式），看起来可以直接一步算出：round(φ^(n+1) / √5)，其中 φ 是黄金分割数。但双精度浮点数只有约 15 到 16 位有效数字，n 变大后就会出误差。下面是真实计算的结果：

滚动变量：五种语言的实现

只需要前两项，不用整个数组：a 是爬到第 i-1 阶的方法数，b 是爬到第 i 阶的方法数，初始都是 1。每一步：(a, b) = (b, a + b)。循环 n - 1 次之后，b 就是爬到第 n 阶的方法数。时间 O(n)，空间 O(1)。Python、Java、Go、JavaScript、C++ 都是真实编译运行的。

Python · 解法代码def solve(n): a, b = 1, 1 # a = 爬到第 i-1 阶的方法数，b = 爬到第 i 阶的方法数（第 0 阶、第 1 阶各有 1 种） for _ in range(n - 1): a, b = b, a + b # 到第 i+1 阶：从第 i 阶爬 1 步，或从第 i-1 阶爬 2 步 return b

Java · 解法代码class Solution { public int climbStairs(int n) { int a = 1, b = 1; // a = 爬到第 i-1 阶的方法数，b = 爬到第 i 阶的方法数 for (int i = 2; i <= n; i++) { int c = a + b; // 到第 i 阶：从第 i-1 阶爬 1 步，或从第 i-2 阶爬 2 步 a = b; b = c; } return b; } }
