LeetCode 78. 子集

给定一个元素互不相同的数组，返回它的所有子集（幂集），包括空集和它本身，顺序不限。n 个元素有 2^n 个子集，因为每个元素"选"或"不选"。这道题有三种常见做法：回溯（每个结点都是一个子集）、位掩码（用 0 到 2^n - 1 的每个整数的二进制位表示选哪些元素）、逐个翻倍（每来一个新元素，把已有的所有子集各复制一份并加上它）。本文在 Python 里实现了这三种，用真实数据验证它们结果一致并比较耗时，给出五种语言的回溯实现，并把回溯过程做成分步演示。

回溯：每个结点都是一个子集

与"组合"（第 77 题）不同的是，这里不需要等到路径满了才收集：走到任何一个结点，当前路径 path 本身就是一个合法的子集。所以每次进入 dfs 就先收集一份 path 的副本，再从 start 起依次尝试加入后面的每个元素，递归，撤销。start 保证元素只往后选，同一个子集不会被排成不同顺序。Python、Java、Go、JavaScript、C++ 都是真实编译运行的。

Python · 解法代码def solve(nums): res, path = [], [] def dfs(start): res.append(path[:]) # 每个结点（每一条路径）本身就是一个子集，不用等到最后 for i in range(start, len(nums)): path.append(nums[i]) dfs(i + 1) # 只往后选，保证同一个子集不会被排列成多种顺序 path.pop() dfs(0) return res

Java · 解法代码class Solution { public List<List<Integer>> subsets(int[] nums) { List<List<Integer>> res = new ArrayList<>(); dfs(nums, 0, new ArrayList<>(), res); return res; } private void dfs(int[] nums, int start, List<Integer> path, List<List<Integer>> res) { res.add(new ArrayList<>(path)); // 每个结点（每一条路径）本身就是一个子集，不用等到最后 for (int i = start; i < nums.length; i++) { path.add(nums[i]); dfs(nums, i + 1, path, res); // 只往后选，保证同一个子集不会被排列成多种顺序 path.remove(path.size() - 1); } } }

三种做法：结果一致，耗时不同

我在 Python 里实现了另外两种做法：位掩码（对每个整数 0 到 2^n - 1，二进制里为 1 的位对应选中的元素）和逐个翻倍。对 n 从 10 到 18 都数出了结果个数是否等于 2^n，n ≤ 14 时还用集合比较了三种做法的结果完全一致，并测了耗时（每个取三次中最快的一次）：

真实实测 · 本机执行输出
三种做法的结果个数（是否都等于 2^n）和耗时（各取三次中最快）：
n=10: 2^n =   1024；回溯     0.15 ms（1024 个）  位掩码     0.46 ms（1024 个）  逐个翻倍     0.07 ms（1024 个）  结果一致：True
n=14: 2^n =  16384；回溯     2.96 ms（16384 个）  位掩码    10.28 ms（16384 个）  逐个翻倍     1.64 ms（16384 个）  结果一致：True
n=16: 2^n =  65536；回溯    13.45 ms（65536 个）  位掩码    46.33 ms（65536 个）  逐个翻倍     8.30 ms（65536 个）  结果一致：未比较
n=18: 2^n = 262144；回溯    64.19 ms（262144 个）  位掩码   231.66 ms（262144 个）  逐个翻倍    57.70 ms（262144 个）  结果一致：未比较

三种做法生成的子集个数都等于 2^n（n = 18 时是 262144 个）。耗时上，逐个翻倍最快（n = 18 时 57.7ms），回溯次之（64.2ms），位掩码最慢（231.7ms），约是回溯的 3.6 倍：位掩码要对每个整数检查 n 个二进制位，总共 n × 2^n 次判断，而回溯和翻倍每生成一个子集只做与它大小成正比的工作。这只是 Python 里的实测，n = 16 和 18 时没有再做结果集合的比较（数量太大），但个数是对的。
