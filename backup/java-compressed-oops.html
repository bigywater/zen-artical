Compressed Oops:对象引用为什么可以用更少位数

为什么堆设成 32 GB 以上对象反而变大?压缩指针的边界在哪里,关掉它每个对象多出多少字节?这篇用 PrintFlagsFinal、堆地址日志和分配字节数把这些数字逐个量出来,并对照 JDK 27 默认开启的紧凑对象头。

31900m / 32g
压缩指针开启的最大堆 / 被关闭的最小堆(对象对齐 8 字节)
155 → 194 MB
500 万个节点的堆占用:开启 → 关闭压缩指针(JDK 21)
8 字节
JDK 27 默认配置下 new Object() 的大小(紧凑对象头)

    本文用到的工具与边界

    • 本机 macOS 27 arm64 / OpenJDK(Temurin 17.0.20、Homebrew 21.0.12 与 27,每篇注明实际用的版本);用 javac 编译、java 直接运行,需要第三方库时用 Maven 解析依赖;计时用 System.nanoTime,数字每次运行会有小幅抖动。JDK 21.0.12 与 JDK 27,SerialGC,macOS Apple Silicon
