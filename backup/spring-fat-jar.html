可执行 jar 的结构与分层 jar

可执行 jar 里面到底是什么?为什么它启动比解压后的目录慢?分层 jar 对 Docker 镜像有什么用?为什么在 IDE 里好用的 getFile() 放进 jar 就报错?这篇打一个 Boot 4.0.8 的 jar,把它解开逐项实测。

JarLauncher
MANIFEST 的 Main-Class 是 JarLauncher,你自己的主类放在 Start-Class
19192 KB 不变 / 5 KB 变
改一个类之后,dependencies 层指纹不变,application 层指纹变化
958 → 770 ms

启动时间

实测 · 本机执行输出 
  java -Djarmode=tools -jar app.jar extract --destination …:退出码 0;输出 ''
    解出来的内容:app.jar、lib/;lib 目录里 34 个 jar
    解出来的 app.jar 的 MANIFEST:Main-Class: demo.Main;Class-Path: lib/commons-logging-1.3.6.jar lib/jackson-annotations-2.21.jar lib/jackson-core-3.1.5.jar lib/jack
  胖 jar:java -jar app.jar:中位 958 ms(范围 906~1051)
  解压后的目录:java -cp BOOT-INF/classes:BOOT-INF/lib/* demo.Main:中位 805 ms(范围 777~823)
  解压后的目录:java org.springframework.boot.loader.launch.JarLauncher:中位 812 ms(范围 803~846)
  tools extract 之后:java -jar extracted/app.jar:中位 770 ms(范围 750~849)

解压后再跑比直接跑胖 jar 快 150 到 190 ms(这个小应用);tools extract 得到的 app.jar 的 Main-Class 就是自己的主类。

分层

实测 · 本机执行输出 
  list-layers(退出码 0):dependencies spring-boot-loader snapshot-dependencies application
  每一层(文件数、大小、内容指纹前 10 位):
    application:1 个文件,5 KB,指纹 84857bb5ce
    dependencies:34 个文件,19192 KB,指纹 91f0390fc9
    snapshot-dependencies:0 个文件,0 KB,指纹 e3b0c44298
    spring-boot-loader:0 个文件,0 KB,指纹 e3b0c44298
  只在应用里多加一个类、重新打包之后:
    application:指纹变了(84857bb5ce → b374aaf948);大小 5 KB → 5 KB
    dependencies:指纹没变;大小 19192 KB → 19192 KB
    snapshot-dependencies:指纹没变;大小 0 KB → 0 KB
    spring-boot-loader:指纹没变;大小 0 KB → 0 KB
  新 app.jar 大小 18.94 MB;分层提取之后,没变的层(dependencies 等)在 Docker 里可以复用缓存,变的只有 application 层

四层中 dependencies 体积最大且改代码后不变,application 只有几 KB,适合做 Docker 的分层缓存。
