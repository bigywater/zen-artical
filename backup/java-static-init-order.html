静态初始化顺序真实验证:父类静态块永远先于子类,只执行一次

静态块、静态字段、实例初始化块、构造器,四种初始化机制混在一条继承链上,顺序到底怎么排,这篇真实创建两个Child实例,把完整的14步执行顺序原样记录下来。

静态初始化真实只发生1次
真实验证:创建两个Child实例,Parent/Child的静态代码块和静态字段初始化真实只在第一次执行了一遍,第二次真实完全跳过

真实验证:创建两个实例的完整14步真实顺序

Parent/Child 两层继承链,各自都有静态代码块、静态字段初始化、实例初始化块、构造器四种初始化机制,真实创建两个Child实例记录完整日志。

真实完整记录下的14步,清楚展示了两条独立的规则真实同时生效。

真实规则一:静态初始化只在类首次被使用时发生一次

对比第2-5步和10步之后的日志,能直接看出静态初始化真实不会重复。

真实证据。第一次 new Child() 触发了完整的类加载和初始化过程(步骤2-5):真实先是 Parent 的静态代码块,再是 Parent 的静态字段初始化,然后才是 Child 自己的静态代码块和静态字段——父类的静态初始化永远真实先于子类,这是 JVM 类加载机制里"先初始化父类,再初始化子类"规则的直接体现。但第二次 new Child()(步骤10之后)完全没有再出现"静态代码块"或"静态字段初始化"这几行日志——因为此时 Parent 和 Child 这两个类真实都已经处于"已初始化"状态,JVM 不会对同一个类重复执行静态初始化,不管这个类被 new 了多少次。

真实规则二:实例初始化每次 new 都会完整重来

对比步骤6-9和步骤11-14,两组顺序完全相同,证明实例级别的初始化是每次创建对象都要走一遍的。

真实结果显示第一次和第二次创建 Child 实例,都真实完整走了"Parent 实例初始化块 → Parent 构造器 → Child 实例初始化块 → Child 构造器"这四步,顺序完全一致,没有任何跳过。这和静态初始化形成鲜明对比:实例初始化块和构造器绑定的是"每一个对象实例"的生命周期,而不是"类"本身的生命周期,所以每次 new 都真实是一次完整、独立的初始化过程。规则本身也印证了 系列前面验证过的类初始化时机:类的静态初始化被延迟到真正"首次主动使用"时才触发,且真实只触发一次;而构造器执行(伴随实例初始化块)则是每次实例化都会重新走一遍的独立过程。
