丢包率对 TCP 吞吐的影响:用延迟与丢包注入实测

丢包对 TCP 的伤害远比“丢了几个包”大得多:每次丢包都让发送方把窗口缩小。这篇用 netlab 在回环上造出 20 ms 和 100 ms 的往返时间,逐档注入 0.1% 到 5% 的随机丢包,看吞吐掉多少、和教科书上的 Mathis 公式吻合到什么程度、RTT 和丢包率各自的影响。

  丢包   2%:RTT 20 ms 吞吐    7.29 MB/s,RTT 100 ms 吞吐    1.40 MB/s,比值 5.2(公式预测 RTT 反比 = 5.0)

同样的丢包率,RTT 5 倍,吞吐之比约 4.6~5.8(0.1% 那一格是 2.7)。

丢包率的影响

实测 · 本机执行输出 
  往返 20 ms:丢包 0.5% → 2%(×4):吞吐 ÷ 2.16(公式预测 ÷ 2.00)
  往返 20 ms:丢包 0.1% → 0.5%(×5):吞吐 ÷ 2.01(公式预测 ÷ 2.24)
  往返 20 ms:丢包 1% → 5%(×5):吞吐 ÷ 2.44(公式预测 ÷ 2.24)
  往返 100 ms:丢包 0.5% → 2%(×4):吞吐 ÷ 2.44(公式预测 ÷ 2.00)
  往返 100 ms:丢包 0.1% → 0.5%(×5):吞吐 ÷ 3.42(公式预测 ÷ 2.24)
  往返 100 ms:丢包 1% → 5%(×5):吞吐 ÷ 1.97(公式预测 ÷ 2.24)

丢包率 ×4,吞吐约 ÷2.2~2.4,符合 1/√p 的量级。

    本文用到的工具与边界

    • 本机 macOS 27 arm64(Apple 芯片)/ Python 3.14.8 / tcpdump(libpcap)/ scapy 2.8 / dpkt / dnspython / h2 / aioquic / OpenSSL / curl 8.7.1;抓包在 lo0(环回)上做,少数实验用真实网卡 en0(这台机器上 en0 是 Wi-Fi,tcpdump 看到的是系统转成以太网格式的帧,所以文中的“以太网头”都指这个 14 字节的头)或访问公网(会在文章里注明);需要丢包 / 延迟 / 限速时,用一个只作用于 lo0 端口 9400-9499 的 dummynet 辅助脚本(netlab);所有服务端都是本机自己起的进程;时间戳取自 tcpdump 的 -tt,数字每次运行会有小幅抖动。全部在 lo0 上(MSS 载荷 16332 字节),netlab 注入每方向延迟 10/50 ms 与单向独立随机丢包;每个组合只测 2 次,每次 5.5 秒窗口,随机丢包下波动大(例如 0.1% 的两次差 30%~60%),表中取均值;发送与接收在同一个进程的线程里
    • 没有验证:真实广域网的丢包模式(突发丢包与随机丢包差别很大,netlab 只造随机丢包);不同拥塞算法(BBR)对丢包的敏感度,本机无法切换;ECN 标记代替丢包的效果;和 w53 的 CUBIC 对比中 Mathis 比值的差别(w53 的 1.04~2.73 与本篇的 0.89~1.21 来自不同的实验设置,没有逐项对齐)
