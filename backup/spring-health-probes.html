健康检查:health 组、liveness 与 readiness 探针

/actuator/health 返回的 503 是怎么来的?数据库挂了 readiness 探针会变吗?liveness 和 readiness 差在哪?健康检查每次都会查数据库吗?这篇在 Spring Boot 4.0.8 上用自己写的指示器逐项实测。

200 / 503
业务检查 DOWN 时,默认配置下整体 /health 是 503,但 /health/readiness 仍是 200
5 次 → 1 次
连续请求 5 次健康检查,myCheck 执行 5 次;设 cache.time-to-live=10s 后只执行 1 次
2057 ms
两个各慢 1000 ms 的指示器,/actuator/health 的用时

liveness 和 readiness 默认开启,components 里有 diskSpace、ping、ssl 和两个 State。

状态聚合

实测 · 本机执行输出 
  myCheck=UP             → /actuator/health 返回 HTTP 200,status=UP
  myCheck=DOWN           → /actuator/health 返回 HTTP 503,status=DOWN
  myCheck=OUT_OF_SERVICE → /actuator/health 返回 HTTP 503,status=OUT_OF_SERVICE
  myCheck=UNKNOWN        → /actuator/health 返回 HTTP 200,status=UP
  myCheck=MY_CUSTOM      → /actuator/health 返回 HTTP 200,status=UP
  -- 自定义映射 management.endpoint.health.status.http-mapping.DOWN=500、http-mapping.MY_CUSTOM=202,order=DOWN,MY_CUSTOM,UP:
  myCheck=DOWN       → HTTP 500,status=DOWN
  myCheck=MY_CUSTOM  → HTTP 202,status=MY_CUSTOM
  myCheck=UP         → HTTP 200,status=UP

DOWN 与 OUT_OF_SERVICE 返回 503;UNKNOWN 和未登记的自定义状态不会改变整体状态;可用 order 和 http-mapping 改。

探针组的成员

实测 · 本机执行输出 
  myCheck=DOWN,默认配置:
    GET /actuator/health → 503 status=DOWN,components=['diskSpace', 'livenessState', 'myCheck', 'other', 'ping', 'readinessState', 'ssl'],groups=['liveness', 'readiness']
    GET /actuator/health/liveness → 200 status=UP
    GET /actuator/health/readiness → 200 status=UP
  myCheck=DOWN,management.endpoint.health.group.readiness.include=readinessState,myCheck:
    GET /actuator/health/liveness → 200 status=UP
    GET /actuator/health/readiness → 503 status=DOWN,components=['myCheck', 'readinessState']
    myCheck 改回 UP 之后:
    GET /actuator/health/readiness → 200 status=UP,components=['myCheck', 'readinessState']
  自定义分组 management.endpoint.health.group.custom.include=myCheck,other(show-details=never):
    GET /actuator/health → 200 status=UP,components=['diskSpace', 'livenessState', 'myCheck', 'other', 'ping', 'readinessState', 'ssl'],groups=['custom', 'liveness', 'readiness']
    GET /actuator/health/custom → 200 status=UP

默认探针组不含业务检查;要让 readiness 反映依赖,要显式 include;liveness 不要放外部依赖。

AvailabilityChangeEvent 可以让 readiness 返回 503 OUT_OF_SERVICE,让 liveness 返回 503 DOWN。

检查的代价

实测 · 本机执行输出 
  默认:连续请求 /actuator/health 5 次,myCheck 被执行了 5 次
  management.endpoint.health.cache.time-to-live=10s:连续请求 5 次,myCheck 被执行了 1 次
  myCheck 和 other 各慢 1000 ms:GET /actuator/health 用时 2057 ms
  同时 GET /actuator/health/liveness 用时 4 ms

每次请求都执行检查,慢检查串行叠加,可用 cache.time-to-live 缓存。
