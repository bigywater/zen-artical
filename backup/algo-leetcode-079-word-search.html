LeetCode 79. 单词搜索

给定一个字母网格和一个单词，判断单词能否由网格中相邻（上下左右）的格子依次连成，同一个格子在一条路径里不能重复使用。做法是回溯（深度优先搜索）：对每个格子作为起点，尝试匹配单词的第一个字符，然后向四个方向继续匹配下一个字符，走过的格子标记为已使用，一条路走不通就撤销标记退回来。本文用真实数据展示两个常见的错误（不撤销标记、完全不标记）各自会错多少，展示最坏情形下的搜索规模，给出五种语言的实现，并把搜索过程做成分步演示。

陷阱：标记不撤销，或者干脆不标记

标记已使用的格子有两个环节都容易出错：第一，一条路径走不通、退回来时，必须把标记撤销，否则别的路径就用不了这个格子；第二，如果压根不标记，同一个格子就会在一条路径里被重复使用。下面是两种错误写法与 solve 的真实结果，最后一行是在 20000 组随机数据上统计的错误比例：

真实实测 · 本机执行输出
# 两种错误写法：标记后不撤销 / 完全不标记
['ABCE', 'SFCS', 'ADEE'], 'ABCCED': 不撤销 -> True；不标记 -> True；solve -> True
['ABCE', 'SFCS', 'ADEE'], 'SEE': 不撤销 -> True；不标记 -> True；solve -> True
['ABCE', 'SFCS', 'ADEE'], 'ABCB': 不撤销 -> False；不标记 -> True；solve -> False

官方示例里不撤销的写法在 ABCCED 和 SEE 上碰巧是对的，ABCB 也对（答案是 False）；不标记的写法则在 ABCB（B 需要重复使用）上错误地返回了 True，AA 里找 AAA 也错误地返回 True。随机数据里（网格和单词的字母都只有 a、b，重复使用同一格的机会很多），不撤销的写法错了 3.9%，不标记的写法错了 13.5%。所以官方示例通过并不代表这两个环节都是对的。

回溯：五种语言的实现

dfs(i, j, k) 表示从格子 (i, j) 出发，匹配单词从第 k 个字符起的后缀：k 等于单词长度说明全部匹配，返回真；越界或者格子字符与 word[k] 不符，返回假；否则把这个格子临时改成 #（不会出现在单词里，等价于"已使用"），依次向下、上、右、左递归，得到结果后把格子改回原来的字符，再返回。最外层对每个格子作为起点尝试一遍。Python、Java、Go、JavaScript、C++ 都是真实编译运行的；Java、Go、C++ 直接在传入的网格上修改（并恢复），Python 和 JavaScript 先复制成字符二维数组。

Python · 解法代码def solve(board, word): g = [list(r) for r in board] m, n = len(g), len(g[0]) def dfs(i, j, k): # 从 (i, j) 出发，匹配 word[k:] if k == len(word): return True if i < 0 or j < 0 or i >= m or j >= n or g[i][j] != word[k]: return False ch = g[i][j] g[i][j] = "#" # 标记为已使用：同一个格子不能重复用 found = dfs(i + 1, j, k + 1) or dfs(i - 1, j, k + 1) or dfs(i, j + 1, k + 1) or dfs(i, j - 1, k + 1) g[i][j] = ch # 回溯：撤销标记，让别的路径还能用这个格子 return found return any(dfs(i, j, 0) for i in range(m) for j in range(n))

Java · 解法代码class Solution { private char[][] g; private String word; private int m, n; public boolean exist(char[][] board, String word) { this.g = board; this.word = word; m = board.length; n = board[0].length; for (int i = 0; i < m; i++) for (int j = 0; j < n; j++) if (dfs(i, j, 0)) return true; return false; } private boolean dfs(int i, int j, int k) { // 从 (i, j) 出发，匹配 word[k..] if (k == word.length()) return true; if (i < 0 || j < 0 || i >= m || j >= n || g[i][j] != word.charAt(k)) return false; char ch = g[i][j]; g[i][j] = '#'; // 标记为已使用：同一个格子不能重复用 boolean found = dfs(i + 1, j, k + 1) || dfs(i - 1, j, k + 1) || dfs(i, j + 1, k + 1) || dfs(i, j - 1, k + 1); g[i][j] = ch; // 回溯：撤销标记，让别的路径还能用这个格子 return found; } }

最坏情形：搜索规模会爆炸

单词搜索的复杂度大致是 O(网格格子数 × 3^L)，L 是单词长度（每一步最多向 3 个新方向走）。最坏的情形是网格里全是同一个字母，单词是很多个这个字母再加上一个网格里没有的字母，这时每条路径都要走到底才发现最后一个字母对不上。我用 5×5 全是 a 的网格，统计单词是 L 个 a 加一个 b 时 dfs 的真实调用次数：

真实实测 · 本机执行输出
最坏情形：5×5 的网格全是 a，单词是 L 个 a 再加一个 b（永远找不到），dfs 的调用次数：
L= 4: dfs 调用      3021 次，结果 False
L= 8: dfs 调用     64605 次，结果 False
L=12: dfs 调用    682301 次，结果 False
L=16: dfs 调用   3873021 次，结果 False

L 每增加 4，调用次数依次增加 21.4 倍、10.6 倍、5.7 倍（3021、64605、682301、3873021）；增长比 3^4 = 81 倍慢，并且越来越慢，因为网格只有 25 个格子，路径不能重复使用格子，能走的方向数越到后面越少。L = 16 时就已经有近 400 万次调用。这也是为什么这道题的单词长度被限制在 15 以内。
