哈希链

实测 · 本机执行输出 
  N = 1000 条审计记录,每条 = JSON 正文 | 上一条的哈希 | 本条哈希。示例第 1 条:{"seq":1,"actor":"user1","action":"read","resource":"/orders/1","outcome":"ok"}|00000000000000000000…
  原始日志校验:全部通过
  篡改第 500 条的正文(把 delete 改成 read,ok 改成 denied):校验失败的第一条 seq = 500
  删除第 500 条:校验失败的第一条 seq = 500(原来第 501 条的上一条哈希对不上了)
  交换第 100 与第 101 条:校验失败的第一条 seq = 100
  删除最后 10 条(截断尾部):无锚点时校验 全部通过(没有发现);用外部保存的最后一条哈希作锚点时校验失败的位置 = 991(= 剩余条数 + 1)
  攻击者从第 500 条起把后面的哈希全部重新计算(普通 SHA-256 链,不需要任何密钥):无锚点校验 全部通过(篡改成功);用外部锚点(原始的最后一条哈希)校验失败的位置 = 1001
  同样的攻击,但日志用 HMAC-SHA256 链(密钥不在攻击者手里):攻击者用普通 SHA-256 重算后,用 HMAC 校验失败的第一条 seq = 500;原始 HMAC 日志校验 全部通过
  HMAC 链:生成 1000 条约 9.2 ms(每条约 9.2 µs),校验 1000 条约 8.2 ms
