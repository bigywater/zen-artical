分布式限流:Redis 令牌桶的原子性

多个实例共用一个令牌桶怎么保证原子?速度能到多少?时间戳该用谁的?Redis 卡住的时候是放行、拒绝还是退回本地?这篇用本机的 Redis 8.10.2 和 Lua 脚本量出来。

3200 对 1000
桶里只有 1000 个令牌时,读-改-写实现与 Lua 脚本各放行的数量(3 轮都一样)
1500 对 509
3 个客户端各 100/s、时钟偏差 0 / +300 / −300 ms 时,用客户端时间戳与用 Redis TIME 的 5 秒放行总数(限额应约 510)
199 / 0 / 188
Redis 暂停的第 2 秒,fail-open、fail-closed、退回本地令牌桶各放行的数量(限额 100/s)

原子性

实测 · 本机执行输出 
  实现                     | 3 轮各放行多少(应为 1000)  | 3 轮结束时桶里剩余令牌(应为 0) | 3 轮 WATCH 冲突重试次数   | 尝试次数/秒(中位数)
  -----------------------+--------------------+--------------------+--------------------+------------
  (a) 读-改-写(不原子)         | 3200 / 3200 / 3200 | 315 / 336 / 338    | 0 / 0 / 0          | 8585       
  (b) WATCH + MULTI/EXEC | 1000 / 1000 / 1000 | 0 / 0 / 0          | 3899 / 3891 / 3893 | 3066       
  (c) Lua 脚本             | 1000 / 1000 / 1000 | 0 / 0 / 0          | 0 / 0 / 0          | 16021

读-改-写会让所有尝试都过;WATCH 靠冲突重试保证,开销大;Lua 脚本在 Redis 里整体原子。

速度

实测 · 本机执行输出 
  场景                  | 吞吐        | 延迟中位数   | p99    
  --------------------+-----------+---------+--------
  热点:16 个线程共用 1 个 key | 16291/秒   | 0.85 ms | 2.87 ms
  分散:每个线程一个 key       | 16364/秒   | 0.84 ms | 2.86 ms
  对照:进程内的令牌桶(一把锁)     | 4157005/秒 | -       | -

热点和分散差别不大;跨进程往返比进程内慢两个数量级。

客户端时钟有偏差时,令牌会被反复补满;用 Redis 的 TIME 最稳。

fail-open 没有限额,fail-closed 全部拒绝,退回本地桶最接近限额。
