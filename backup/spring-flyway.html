Flyway:迁移顺序、校验和与失败后的状态

Flyway 的脚本按什么顺序执行?改了已经执行过的脚本会怎样?脚本执行到一半失败了库是什么状态?已有表的库怎么接入?这篇在 Spring Boot 4.0.8、Flyway 11、MySQL 上逐个实测。

失败状态

  V2 里第一条建表成功、第二条出错:启动失败

    历史表:2 行
      rank 1 version 1 "create a" SQL checksum -1193849269 success=1
      rank 2 version 2 "two statements" SQL checksum 1582595889 success=0
    业务表:['a', 't2']
  不改任何东西再启动一次:启动失败
    Caused by: org.flywaydb.core.api.exception.FlywayValidateException: Validate failed: Migrations have failed validation ‖ Detected failed migration to version 2 (two statements).
    历史表:2 行

      rank 2 version 2 "two statements" SQL checksum 1582595889 success=0
    业务表:['a', 't2']

MySQL 的 DDL 不能回滚,脚本中途失败留下半截对象和 success=0 的行,需要 repair 加手工清理。

      rank 2 version 2 "create b" SQL checksum 1407251784 success=1

非空库默认拒绝;baseline-on-migrate 的基线版本默认 1,会跳过 V1。
