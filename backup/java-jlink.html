jlink:裁剪出应用需要的 Java 运行时

jlink 可以把 JDK 裁剪成只含应用所需模块的运行时。jdeps 能找出需要的模块吗?各个选项能省多少体积?裁剪之后启动时间会变吗?漏掉一个反射依赖会怎样?这篇用一个真实应用逐项测量。

350 → 30.0 MB
完整 JDK 21 → jdeps 模块 + strip-debug + zip-9 的 jlink 镜像
40 → 24 ms
jlink 镜像加 --generate-cds-archive 前后的 Hello 启动时间
163.1 MB
java.base 加 --bind-services 之后的镜像大小

jdeps 找模块

实测 · 本机执行输出 
  jdeps --print-module-deps app.jar → java.base,java.logging,java.net.http 
  jdeps -s(摘要): app.jar -> java.base | app.jar -> java.logging | app.jar -> java.net.http
  完整 JDK 21 的模块数:69;目录大小 350 MB

jlink 选项与体积

实测 · 本机执行输出 
  java.base 只有 base                    47.3 MB,jlink 耗时 0.5 s
  jdeps 给出的模块                          49.3 MB,jlink 耗时 0.5 s
  jdeps 的模块 + --strip-debug            44.5 MB,jlink 耗时 1.0 s
  + --compress=zip-6                   30.0 MB,jlink 耗时 1.6 s
  + --compress=zip-9                   30.0 MB,jlink 耗时 1.7 s
  不加任何选项                               49.8 MB,jlink 耗时 0.5 s
  zip-9 + --generate-cds-archive       56.6 MB,jlink 耗时 3.1 s
  对照:完整 JDK 21 350 MB;jdeps 的模块 + strip-debug + zip-9 是它的 9%
  带 --generate-cds-archive 的镜像里的 CDS 归档文件: ['classes_nocoops.jsa 13.5 MB', 'classes.jsa 13.2 MB']
  最小镜像(zip-9)的 java --list-modules: ['java.base@21.0.12.1', 'java.logging@21.0.12.1', 'java.net.http@21.0.12.1']
