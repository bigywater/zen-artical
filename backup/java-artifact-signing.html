Java 发布产物签名

发布产物的签名回答的是“这个文件是谁发布的、有没有被改过”。这篇真实签名并篡改一个 jar,对照 jarsigner 与运行时的反应,再用 PGP 分离签名演示为什么校验和不能代替签名,并量出签名的运行时开销。

SecurityException
改了已签名类的字符串后,jarsigner -verify 与 java -cp 运行都抛 SHA-384 digest error;未签名的 jar 上同样的改动无任何报错
verified
攻击者改类后用自己的证书重新签名,jarsigner -verify 仍然是 jar verified.(签名者是 CN=Attacker)
1.19 倍
签名后 jar 加载 1000 个类的耗时比值(76 ms → 90 ms)

校验和与 PGP 签名

实测 · 本机执行输出 
  发布者密钥:RSA 2048,指纹 3efeae14848730b475645f16d75f382b6c8f1eae,key id d75f382b6c8f1eae;另一个无关密钥 key id 9c897dd80479c601
  app.jar 的分离签名 app.jar.asc:485 字节,首行 -----BEGIN PGP SIGNATURE-----,末行 -----END PGP SIGNATURE-----;app.jar 1144 字节(签名大小与 jar 大小无关)
  用发布者的公钥验证原始 jar:true;验证被篡改的 jar:false;用无关的公钥验证原始 jar:false
  攻击者同时替换 jar 与 .sha256 文件:下载到的 jar 的 SHA-256 86f2aeaff02dd8d1… 与替换后的 .sha256 文件内容 86f2aeaff02dd8d1… 相等:true(校验和检查通过);而 .asc 还是发布者的签名:false(签名检查失败)
  攻击者也替换 .asc(用自己的密钥 d0820345889b3e0c 签名):用攻击者的公钥验证 true,用发布者的公钥验证 false(签名通过与否取决于你信任哪把公钥)
  原始 jar 只翻转 1 个比特:SHA-256 前 16 位 20d6d5a8e621bc39 → 1816b9635a64e0af,签名验证 false

运行时开销

实测 · 本机执行输出 
  1000 个类,每个新 JVM 里 Class.forName + 调用一次(9 次取中位数):未签名 76 ms(最小 74、最大 78),签名后 90 ms(最小 89、最大 91),比值 1.19
  jar 大小:未签名 291734 字节,签名后 405634 字节;MANIFEST.MF 里的摘要条目 1001 条
