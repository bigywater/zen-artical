LinkExtractor:链接是怎么被找到并过滤的

LinkExtractor 是怎么把页面里的链接找出来并过滤的? 怎么生效、重复怎么去、哪些扩展名默认被丢掉、allow 匹配的是什么、rel=nofollow 管不管?这篇用一个精心准备的页面把每个参数跑一遍。

规范化

实测 · 本机执行输出 
  unique=True(默认): 13 个;unique=False: 14 个
  query 两个链接(page?b=2&a=1 / page?a=1&b=2)默认 unique:2 个
      http://site.test/docs/page?b=2&a=1      text='query'               nofollow=False
      http://site.test/docs/page?a=1&b=2      text='query2'              nofollow=False
  canonicalize=True:1 个
      http://site.test/docs/page?a=1&b=2      text='query'               nofollow=False
  process_value 用于 attrs=("onclick",):1 个
      http://site.test/from-onclick           text='onclick'             nofollow=False

canonicalize=True 把查询参数排序等规范化后再去重;process_value 可以改写属性值。

默认丢掉 91 种扩展名(压缩包、图片、音视频、文档等);deny_extensions 可以自定义。

细节

实测 · 本机执行输出 
  /nofollow 的 nofollow = [True] (链接仍被提取)
  href="#frag" 的链接是否被提取: True | href 以 mailto: 开头: False | javascript:: False
  <area href="/area"> 是否被提取: True
  嵌套文本 <a><b>nested</b> text</a> 的 text = ['nested text']
  Link 对象的字段: ['fragment', 'nofollow', 'text', 'url']

nofollow 只记录不过滤,片段链接会保留,文字取嵌套标签的全部文本。
