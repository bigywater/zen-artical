@Retryable:Spring Framework 7 内置的重试、退避与异常筛选(以及 @ConcurrencyLimit)

Spring 7 把重试做进了框架本身:@Retryable 默认怎么重试?退避怎么算?哪些异常会被重试?用完次数之后调用者看到什么?RetryTemplate 又是什么样?这篇在 Spring Framework 7.0.9 上用带时间戳的时间线逐项验证,也顺带验证了同包的 @ConcurrencyLimit。

1 加 3 次
默认 maxRetries = 3 时一个总是失败的方法最多执行的次数(delay 默认 1000 ms)
100、200、400、500、500
delay = 100、multiplier = 2、maxDelay = 500 时各次重试之间的等待(ms,实测约 108、204、404、505、505)
1219 对 305 ms

    110 ms  RetryListener.onRetryFailure(总是失败)

编程式重试,监听器只管“重试”,次数用完抛 RetryException。

@ConcurrencyLimit

实测 · 本机执行输出 
    @ConcurrencyLimit(2),8 个线程同时调用一个耗时 300 ms 的方法:成功 8 个,被拒绝 0 个,全部结束花了 1219 ms,方法内观察到的最大并发 2
    @ConcurrencyLimit(2, policy = REJECT),8 个线程同时调用一个耗时 300 ms 的方法:成功 2 个,被拒绝 6 个(InvocationRejectedException),全部结束花了 305 ms

限制同一个方法的并发数,多余的排队或拒绝。
