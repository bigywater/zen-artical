Flask 请求与数据库事务边界

一个请求到底是不是一个事务?视图里出错时哪些写入会留下?事务拖得久会怎样?这篇用真实的 PostgreSQL 与多线程的 gunicorn,把事务边界的每个情形跑一遍。

原子性

实测 · 本机执行输出 
  /atomic → HTTP 500 | 库里有没有 z-a: False

出错之后继续用 session

实测 · 本机执行输出 
   {"after_rollback":true,"first":"IntegrityError","second":"PendingRollbackError"}
  已经执行过查询(事务已自动开始)再调 db.session.begin(): {"begin":"InvalidRequestError: A transaction is already begun on this Session."}
  begin_nested(保存点)里违反唯一约束:只回滚保存点,外层的 sp-keep 仍被提交: True

长事务与锁

实测 · 本机执行输出 
  B 更新同一行:等了 1382 ms(A 总共 1684 ms)
  有请求在做只读查询后睡 1.5 秒(没 commit,连接 idle in transaction):B 更新只用了 2 ms

并发用的是 gunicorn 的 gthread worker,B 请求在 A 之后 0.3 秒发出。
