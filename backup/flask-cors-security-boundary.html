CORS 安全边界

CORS 配置写成什么样才算安全?带 cookie 的接口能用通配符吗?用正则匹配来源要注意什么?CORS 能挡住 curl 吗?这篇只检查响应头:对几种配置分别发不同的 Origin,看服务端回什么。

任意 Origin
默认或 "*" 加 supports_credentials 时回显的来源范围
evilexample.com
不严的正则 https://.*example.com 会放行的别人的域名
200
Origin 不在名单里的请求,服务端仍然处理并返回的状态码

常见配置对不同 Origin

实测 · 本机执行输出 
  [origins 不写(默认 *)]
     Origin: https://app.example.com  → {'Access-Control-Allow-Origin': 'https://app.example.com', 'Vary': 'Origin'}
     Origin: https://other.test       → {'Access-Control-Allow-Origin': 'https://other.test', 'Vary': 'Origin'}
     Origin: null                     → {'Access-Control-Allow-Origin': 'null', 'Vary': 'Origin'}
  [origins="*" + supports_credentials=True]
     Origin: https://app.example.com  → {'Access-Control-Allow-Origin': 'https://app.example.com', 'Access-Control-Allow-Credentials': 'true', 'Vary': 'Origin'}
     Origin: https://other.test       → {'Access-Control-Allow-Origin': 'https://other.test', 'Access-Control-Allow-Credentials': 'true', 'Vary': 'Origin'}
     Origin: null                     → {'Access-Control-Allow-Origin': 'null', 'Access-Control-Allow-Credentials': 'true', 'Vary': 'Origin'}
  [origins=[自己的前端]]
     Origin: https://app.example.com  → {'Access-Control-Allow-Origin': 'https://app.example.com'}
     Origin: https://other.test       → {}
     Origin: null                     → {}
  [origins=[自己的前端] + supports_credentials]
     Origin: https://app.example.com  → {'Access-Control-Allow-Origin': 'https://app.example.com', 'Access-Control-Allow-Credentials': 'true'}
     Origin: https://other.test       → {}
     Origin: null                     → {}

正则匹配的陷阱

实测 · 本机执行输出 
  [r"https://.*example.com"(不严)]
     https://app.example.com                    → 放行
     https://evilexample.com                    → 放行
     https://app.example.com.other.test         → 放行
     http://app.example.com                     → 拒绝
     https://sub.app.example.com                → 放行
  [r"https://app\.example\.com$"(锚定)]
     https://app.example.com                    → 放行
     https://evilexample.com                    → 拒绝
     https://app.example.com.other.test         → 拒绝
     http://app.example.com                     → 拒绝
     https://sub.app.example.com                → 拒绝
  [r"https://([a-z0-9-]+\.)?example\.com$"(允许子域)]
     https://app.example.com                    → 放行
     https://evilexample.com                    → 拒绝
     https://app.example.com.other.test         → 拒绝
     http://app.example.com                     → 拒绝
     https://sub.app.example.com                → 拒绝
