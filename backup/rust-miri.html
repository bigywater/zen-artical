Miri 检查未定义行为

一段 unsafe 代码在普通运行里没报错,是不是就没有问题?这篇把几种典型的未定义行为各写一个最小程序,先用普通编译运行,再用 Miri 解释执行,对比它们的结果、报错内容,以及 Miri 的代价与限制。

Miri
本步的对象

    本文用到的工具与边界

    • 本机 macOS 27 arm64 / rustc 1.98.1(brew)/ cargo 1.98.1;单个文件用 rustc 直接编译,需要依赖时用 cargo(经代理从 crates.io 下载);计时用 std::time::Instant,数字每次运行会有小幅抖动。nightly 工具链用 rustup 装在隔离目录(不影响 brew 的 rustc):rustc 1.101.0-nightly (21b707e3f 2026-09-30)、miri 0.1.0 (21b707e3f9 2026-09-30)。cargo miri run(默认的 Stacked Borrows;另用 -Zmiri-tree-borrows)
    • 没有验证:Miri 对更多目标平台(-Zmiri-many-seeds 以外的随机化)的行为、-Zmiri-many-seeds 对线程调度的覆盖效果、在大型真实 crate 测试套件上跑 cargo miri test 的耗时、Miri 对内联汇编与更多 FFI 的支持、Stacked 与 Tree Borrows 在更复杂代码上结论不同的情况
