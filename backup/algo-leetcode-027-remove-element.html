LeetCode 27. 移除元素

给定一个数组和一个值 val，原地移除数组中所有等于 val 的元素，返回剩下的元素个数 k；前 k 个位置放剩下的元素，顺序可以任意，后面的内容不重要。这是双指针的入门题：一个指针 i 扫描，一个指针 k 指向下一个要写入的位置。本文除了给出五种语言的实现，还比较了另一种"用最后一个元素补位"的做法，用真实的写入次数展示两种做法在不同数据上各有优劣，并把双指针做成分步演示。

双指针：五种语言的实现

k 指向下一个要写入的位置。从左到右扫描，遇到不等于 val 的元素就写到 nums[k] 并让 k 加一，等于 val 的直接跳过。扫描结束时 nums[0..k) 就是所有保留的元素，并且保留了它们原来的相对顺序。Python、Java、Go、JavaScript、C++ 都是真实编译运行的。

Python · 解法代码def solve(nums, val): k = 0 # nums[0:k] 是已经留下的、不等于 val 的元素 for x in nums: if x != val: nums[k] = x k += 1 return [k, nums[:k]]

Java · 解法代码class Solution { public int removeElement(int[] nums, int val) { int k = 0; // nums[0..k) 是已经留下的、不等于 val 的元素 for (int x : nums) { if (x != val) nums[k++] = x; } return k; } }

另一种做法：从后往前补位

题目允许改变元素顺序，所以还有另一种做法：遇到等于 val 的元素，就用数组最后一个元素覆盖它，然后数组长度减一，并且这个位置要再检查一次（因为换过来的元素也可能等于 val）。这种做法在 val 很少的时候只需要很少的写入。下面是长度 100000 的数组，val 占不同比例时，两种做法真实的写入次数：

真实实测 · 本机执行输出
写入次数对比：长度 100000，val 在数组里占不同比例
val 占  1%: 正向覆盖写入  99000 次，从后往前补位写入   1000 次，保留个数 99000/99000
val 占 10%: 正向覆盖写入  90000 次，从后往前补位写入  10000 次，保留个数 90000/90000
val 占 50%: 正向覆盖写入  50000 次，从后往前补位写入  50000 次，保留个数 50000/50000
val 占 99%: 正向覆盖写入   1000 次，从后往前补位写入  99000 次，保留个数 1000/1000

val 占 1% 时，正向覆盖写了 99000 次，从后往前补位只写了 1000 次；val 占 50% 时两者相同（都是 50000 次）；val 占 99% 时反过来：正向覆盖只写 1000 次，从后往前补位写了 99000 次。哪种更省写入取决于 val 在数据中的比例。补位法的代价是会改变保留元素的相对顺序，而正向覆盖保持顺序。这个实验只数了写入次数，没有测量实际耗时。
