Bean Validation:把约束声明在模型边界

Bean Validation 一行注解就能表达约束,但 null、空串、级联、分组与消息模板各有细节。这篇用 Hibernate Validator 逐项实测,也包括自定义消息模板里的注入风险与验证的成本。

null 合法
@Size、@Pattern、@Email、@Min、@Past、@Positive 对 null 都视为合法,要拒绝 null 需要 @NotNull
{key} 仍被插值
自定义约束的消息模板中,${...} 不求值,但 {jakarta.validation.constraints.NotNull.message} 这样的消息参数仍被替换
3.1 ms vs 约 2 µs
每次验证都新建 ValidatorFactory 与复用 Validator 的稳态单次验证耗时

方法与构造器验证

自定义约束、消息模板与语言

实测 · 本机执行输出 
  [custom]
  类级别约束 @Same(两次密码不一致):
        pw2 → “两次输入不一致”(值 “Main$Signup@647e447”)
  一致:(没有违规)
  消息模板里的表达式:自定义验证器用 buildConstraintViolationWithTemplate("用户输入:" + 用户文本),文本是 ${1+1}:
         → “用户输入:${1+1}”(值 “Main$Msg@359f7cdf”)
  同样,文本是 #{1+1}:
         → “用户输入:#{1+1}”(值 “Main$Msg@1fa268de”)

         → “用户输入:${validatedValue}”(值 “Main$Msg@4f6ee6e4”)
  文本是 {jakarta.validation.constraints.NotNull.message}(消息键):
         → “用户输入:must not be null”(值 “Main$Msg@4466af20”)
  文本是 ${''.getClass().forName('java.lang.Runtime')}(尝试反射):
         → “用户输入:${''.getClass().forName('java.lang.Runtime')}”(值 “Main$Msg@a514af7”)
  注解里的 message 可以引用 {min} 与 ${validatedValue}:
        s → “至少 5 个字符,当前值 ab”(值 “ab”)

成本与线程安全

实测 · 本机执行输出 
  [cost]
  JVM 里第一次 buildDefaultValidatorFactory 78 ms;同一 JVM 里第二次构建 1 ms;getValidator 0.65 ms;对 User 第一次 validate(含解析约束元数据)42 ms
  稳态(同样的字段,无 address 级联):合法的 User(0 个违规)1.81 µs / 次;3 个违规的 User(name 空白、age 5、email 不合法,要生成消息)2.16 µs / 次
  带 @Valid address 级联的合法 User:2.36 µs / 次
  反面做法:每次验证都新建 ValidatorFactory:平均 3.1 ms / 次(对比稳态的几 µs)
  failFast(true):全部违规的 User 返回 1 条违规(默认 4 条)
  8 个线程共用同一个 Validator 各验证 2 万次(合法 / 非法交替):结果不对 0 次
