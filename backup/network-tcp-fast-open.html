TCP Fast Open:把数据塞进 SYN

TCP Fast Open 想把“握手一个往返 + 请求应答一个往返”压成一个往返:第一次连接拿一个 cookie,以后的连接把数据直接塞进 SYN。这篇先在 macOS 上实测它在线上长什么样、能省多少时间、公网上谁支持,再用 root 权限补上密钥轮换和“客户端为什么悄悄不用了”,最后在 Linux 容器里对照 Linux 的行为、重放和被中间设备丢弃的情形。

202 → 101 ms
50 ms 单向延迟的链路上,普通 connect + send 与 SYN 带数据的 connectx 的耗时中位数
3 次重传后停用
macOS 在 SYN 带数据重传 3 次后对该目的地不再发 TFO 选项,至少 40 分钟没有恢复
5 次
被重放的 SYN 让 Linux 服务端应用读到同一份数据的次数(含原始 1 次)
← 上一篇 SO_REUSEADDR 与 SO_REUSEPORT:端口复用的两种含义

  (容器网卡开着发送校验和卸载,抓到的出站包里 TCP 校验和是占位值,直接重发会被服务端丢弃——第一次尝试时服务端计数 TcpInCsumErrors = 2,重发的包没有生效;下面是重新计算校验和之后的结果)
  抓到的 SYN:载荷 7 字节,TFO 选项长度 [10]
