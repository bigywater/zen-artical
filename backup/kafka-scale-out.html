验证：加入新broker，已有topic的副本分布真实一个字节都不会变

这一点本系列《Broker 加入和离开集群时发生什么》已经验证过：新broker加入后，已有topic的Replicas列表真实完全不受影响，不会自动把数据挪过去分摊负载。

验证：--generate真实会把新broker算进候选分配方案

命令 · shell $ cat topics-to-move.json {"version":1,"topics":[{"topic":"leader-demo"}]} $ kafka-reassign-partitions.sh --bootstrap-server localhost:19092 \ --topics-to-move-json-file topics-to-move.json --broker-list "1,2,3,4" --generate
真实实测 · 本机执行输出 
Current partition replica assignment
{"partitions":[{"topic":"leader-demo","partition":0,"replicas":[1,2,3]},
                {"topic":"leader-demo","partition":1,"replicas":[2,3,1]}, ...]}

Proposed partition reassignment configuration
{"partitions":[{"topic":"leader-demo","partition":0,"replicas":[1,2,3]},
                {"topic":"leader-demo","partition":1,"replicas":[2,3,4]},  ← 真实用上了broker4
                {"topic":"leader-demo","partition":2,"replicas":[3,4,1]},  ← 真实用上了broker4
                {"topic":"leader-demo","partition":3,"replicas":[4,1,2]},  ← 真实用上了broker4
                {"topic":"leader-demo","partition":4,"replicas":[1,3,4]},  ← 真实用上了broker4
                {"topic":"leader-demo","partition":5,"replicas":[3,4,2]}]} ← 真实用上了broker4
--broker-list参数里真实一旦包含了新加入的broker4，工具生成的方案就会真实把它编织进几乎每一个分区的副本列表——6个分区里5个真实分到了broker4。这份"Proposed"配置本身不会真实生效，--generate只是真实算出一份建议方案并打印出来，需要真实另存成文件、再用--execute才会真正触发数据搬迁(跟《Partition Reassignment》那篇的手动JSON是同一个执行机制，只是这里的JSON是工具自动算出来的，不用自己手写)。
