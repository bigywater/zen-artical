序列化器

实测 · 本机执行输出 
  自动配置的 RedisTemplate 的 key / value 序列化器:JdkSerializationRedisSerializer / JdkSerializationRedisSerializer;StringRedisTemplate:StringRedisSerializer / StringRedisSerializer
  读回来:jdk → User[alice,30,[a, b]];json → {age=30, name=alice, tags=[a, b]}
  redis 里的 key b'json:user':value 共 42 字节,前 60 字节 b'{"age":30,"name":"alice","tags":["a","b"]}'
  redis 里的 key b'str:name':value 共 5 字节,前 60 字节 b'alice'
  redis 里的 key b'\xac\xed\x00\x05t\x00\x08jdk:user':value 共 161 字节,前 60 字节 b'\xac\xed\x00\x05sr\x00\tdemo.User4>2S\xe9\xcfg\xa5\x02\x00\x03I\x00\x03ageL\x00\x04namet\x00\x12Ljava/lang/Strin'

默认 RedisTemplate 用 JDK 序列化:key 带头、value 大、其他语言读不了;StringRedisTemplate 与 JSON 序列化器是可读的。

Lettuce 的连接

实测 · 本机执行输出 
  -- classpath 上没有 commons-pool2(默认):
    Lettuce 默认的命令超时 = PT1M,连接超时 = PT10S;是否用连接池:false
    空闲时 connected_clients = 1
    64 个线程并发 GET 3 秒:共 286436 次(95479 次/秒);压测中间 connected_clients = 1
  -- classpath 上有 commons-pool2(Boot 因此自动启用连接池):
    Lettuce 默认的命令超时 = PT1M,连接超时 = PT10S;是否用连接池:true
    空闲时 connected_clients = 1
    64 个线程并发 GET 3 秒:共 285830 次(95277 次/秒);压测中间 connected_clients = 1
  -- 有 commons-pool2,再把 spring.data.redis.lettuce.pool.enabled 显式设成 false:
    Lettuce 默认的命令超时 = PT1M,连接超时 = PT10S;是否用连接池:false
    空闲时 connected_clients = 1
    64 个线程并发 GET 3 秒:共 305869 次(101956 次/秒);压测中间 connected_clients = 1
  -- 有 commons-pool2,并把 shareNativeConnection 关掉(每次操作都从池里借连接,max-active=8):
    Lettuce 默认的命令超时 = PT1M,连接超时 = PT10S;是否用连接池:true
    空闲时 connected_clients = 1
    64 个线程并发 GET 3 秒:共 163349 次(54450 次/秒);压测中间 connected_clients = 8

默认所有线程共用一个连接;有 commons-pool2 也不一定真的用池;不共享连接的池反而更慢。

pipeline

实测 · 本机执行输出 
  循环里一个一个 set:10000 个 key,中位 461 ms(378~624);dbsize = 10000
  executePipelined:10000 个 key,中位 67 ms(60~121);dbsize = 10000
  multiSet(一条 MSET):10000 个 key,中位 10 ms(8~12);dbsize = 10000

往返次数是主要代价:循环 461 ms,pipeline 67 ms,MSET 10 ms。
