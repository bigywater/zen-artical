@Lazy 与懒加载:启动时间与首次请求代价的取舍

@Lazy 能把启动时间省多少、代价挪到了哪里?配置错误还能在启动时发现吗?注入点上的 @Lazy 和 Bean 上的 @Lazy 有什么区别?带 @EventListener 的 Bean 能不能懒加载?这篇在 Spring Framework 7.0.9 上逐项验证。

1263 → 86 ms
50 个构造要 20 ms 的单例,饿汉与懒加载的 refresh() 耗时
127 ms
懒加载之后第一次取其中 5 个的耗时,代价被挪到第一次使用
三处不推迟
@Bean @Lazy、@Configuration @Lazy 和普通单例上的 @EventListener Bean,在 refresh 时都被构造

省的是启动时间

实测 · 本机执行输出 
  饿汉 10 个 Heavy(构造器各睡 20 ms):refresh() 312 ms;之后第一次取其中 5 个 0 ms;再取这 5 个 0 ms;已创建的单例数 23
  懒加载 10 个 Heavy(构造器各睡 20 ms):refresh() 65 ms;之后第一次取其中 5 个 124 ms;再取这 5 个 0 ms;已创建的单例数 18
  饿汉 50 个 Heavy(构造器各睡 20 ms):refresh() 1263 ms;之后第一次取其中 5 个 0 ms;再取这 5 个 0 ms;已创建的单例数 63
  懒加载 50 个 Heavy(构造器各睡 20 ms):refresh() 86 ms;之后第一次取其中 5 个 127 ms;再取这 5 个 0 ms;已创建的单例数 18

懒加载把构造代价从 refresh 挪到第一次使用,总工作量不变。

错误被推迟

实测 · 本机执行输出 
  eager:refresh() 就失败了:UnsatisfiedDependencyException
  lazy:refresh() 成功(没有发现 Missing 缺失)
    第一次 getBean("fails") 才失败:UnsatisfiedDependencyException: No qualifying bean of type 'Missing' available: expected at least 1 bean which qualifies as autowire candidate. Dependency annotations: {}

依赖缺失这类错误在懒加载下要到第一次使用才抛出。

  5. User 调用完 heavy.hi()
  6. heavy 字段的类型:Main$Heavy$$…(CGLIB 代理)

  1. 构造 User(heavy 字段是 @Lazy 注入)
  2. --- refresh 完成,调用 use()

  4. 构造 Heavy(目标 Bean 标了 @Lazy)
  5. User 调用完 heavy.hi()
  6. heavy 字段的类型:Main$Heavy$$…(CGLIB 代理)
  --- 场景 c
  1. 构造 UserPlain(heavy 字段是普通 @Autowired)
  2. 构造 Heavy(目标 Bean 标了 @Lazy)

  5. UserPlain 调用完 heavy.hi()

只推迟解析,目标和注入点两处都 @Lazy 才推迟创建。

带 @EventListener 的 Bean 不会被推迟。

全局懒加载

实测 · 本机执行输出 
  SpringApplication.setLazyInitialization(false):启动后单例 22 个;HeavyBean 已构造?true
  SpringApplication.setLazyInitialization(true):启动后单例 20 个;HeavyBean 已构造?false

SpringApplication.setLazyInitialization(true) 一次性让所有 Bean 懒加载。
