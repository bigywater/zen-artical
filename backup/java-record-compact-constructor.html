Record 紧凑构造器真实验证:在构造器里修改参数,真实字段值也会跟着变

紧凑构造器(compact constructor)是Record最实用的特性之一——省略参数列表，直接对隐式参数做校验或修正。这篇真实验证它到底能做到什么程度，尤其是"修改参数变量"这个操作是否真的会影响最终字段。

真实验证:紧凑构造器真实能做参数校验

最常见的用法:在构造对象之前，用紧凑构造器拦截非法参数组合。

RecordCompactConstructorDemo.java record Range(int min, int max) { Range { // 紧凑构造器：没有参数列表，隐式使用min和max if (min > max) throw new IllegalArgumentException("min不能大于max: " + min + " > " + max); } } new Range(10, 5);
真实实测 
真实捕获校验异常: min不能大于max: 10 > 5

真实结果证明紧凑构造器里的校验逻辑真实生效——传入 min=10, max=5 这种非法组合,对象创建过程真实被中断,IllegalArgumentException 真实被抛出,不会得到一个内部状态不一致的 Range 实例。

真实验证:在紧凑构造器里修改参数,真实影响最终字段值

紧凑构造器不只能校验，还能对参数变量重新赋值——这次修改是否真的会体现在对象的字段上？

RecordCompactConstructorDemo.java Range { if (min < 0) { min = 0; // 真实重新赋值参数变量 } } Range r = new Range(-5, 10);
真实实测 
真实在紧凑构造器里把负数min修正为0
真实构造完成后 r.min() = 0（应该是修正后的0，不是传入的-5）
Range.min 字段真实是final: true
Range真实的构造器个数: 1
构造器真实参数: [int, int]
真实的编译器魔法在这里。紧凑构造器在字节码层面被编译器真实展开成一个完整的、带参数列表的构造器——它会真实在紧凑构造器体执行完毕之后,自动追加一段"把（可能已被修改的）参数值赋给同名字段"的代码,这一步是编译器隐式插入的,不需要开发者手写 this.min = min;。真实验证证明这个隐式赋值用的是紧凑构造器执行完之后参数变量当时的值,不是最初传入构造器的原始值——所以在紧凑构造器里对 min 重新赋值为 0,这个 0 才是真实最终写进 Range.min 这个 final 字段的值。反射也验证了这个字段依然真实是 final 的,构造器的真实参数签名和普通的两参数构造器没有任何区别——紧凑构造器只是源码层面的语法简化,不改变编译产物的本质结构。
