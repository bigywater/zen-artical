线程异常、进程异常：主程序如何感知后台失败

真实对比裸threading.Thread、ThreadPoolExecutor和multiprocessing.Process三种后台执行方式在异常发生后，主程序真实能感知到多少信息。

裸Thread异常
真实主线程join()正常返回，完全无法感知
ThreadPoolExecutor
真实fut.result()能重新抛出原始异常
multiprocessing.Process

验证：裸threading.Thread的异常，主线程真实完全感知不到

实测 · 本机执行输出 
Exception in thread Thread-1 (bad_thread):     ← 真实这段traceback只是打印到stderr
Traceback (most recent call last):
  ...
ValueError: thread blew up

main: thread.join() returned normally, main thread is completely unaware anything went wrong
main: is_alive? False
main: program continues running fine

这是threading.Thread真实最容易被忽视的一个特性：子线程里没有被捕获的异常，真实不会以任何形式传播回主线程——t.join()真实正常返回，不会抛出任何异常，主线程的程序逻辑完全没有办法通过正常的try/except感知到子线程失败过。控制台上那段Exception in thread ...的traceback，真实只是Python默认的threading.excepthook把它打印到了stderr——这是给人看的日志，不是程序可以捕获处理的信号；如果这个线程跑在一个没人盯着日志的后台服务里，这次失败真实会被完全静默地吞掉，唯一能观察到的副作用只有t.is_alive()变成False。

验证：ThreadPoolExecutor真实把异常包进了Future，fut.result()才炸出来

实测 · 本机执行输出 
main: caught the real exception via fut.result(): task blew up
这是concurrent.futures相比裸threading.Thread真实提供的关键改进：submit()返回的Future对象真实会捕获子线程里发生的异常并存起来，调用方只要真实调用fut.result()，如果对应的任务当初真的抛过异常，这次调用会真实把那个原始异常对象重新raise出来，可以被主线程正常的try/except接住——这跟裸Thread那种"异常直接在后台丢失"的默认行为是真实的本质区别。这也是本系列很多真实项目建议优先用ThreadPoolExecutor而不是手写threading.Thread的原因之一：异常处理这件事，前者把"结果和异常"统一封装进了Future这个真实可查询的对象，后者则完全需要业务代码自己额外想办法（比如在线程函数内部手动try/except再塞进一个队列）才能把异常传回来。

验证：multiprocessing子进程崩溃，父进程真实连异常对象本身都看不到

实测 · 本机执行输出 
Process Process-1:
Traceback (most recent call last):
  ...
ValueError: process blew up

main: process exitcode = 1     ← 真实父进程只能拿到这个数字
main: main process itself never saw the ValueError object, only the exit code

这一层比线程更彻底：子进程真实是一个独立的操作系统进程，有自己独立的内存空间，ValueError这个异常对象本身真实根本不可能跨进程边界直接传递——子进程崩溃打印的那段traceback，是子进程自己往它自己的stderr（真实通常会被继承并汇聚到同一个终端）打印的，父进程能拿到的真实只有一个整数exitcode（正常退出是0，未捕获异常导致的崩溃这次真实是1）。如果真的需要知道子进程失败的具体原因，真实必须显式设计——比如子进程内部捕获异常后把错误信息通过multiprocessing.Queue或者Pipe发回父进程，或者用concurrent.futures.ProcessPoolExecutor（它内部真实做了类似ThreadPoolExecutor的封装，会把子进程的异常序列化后通过Future.result()重新抛出）——裸multiprocessing.Process不会替你做这件事。
