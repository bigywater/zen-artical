LeetCode 49. 字母异位词分组

给定一个字符串数组，把互为字母异位词（字母相同、排列不同）的字符串分到同一组。核心问题是"怎么判断两个字符串是异位词"：把每个字符串的字母排序，异位词排序后完全相同，把这个排序后的字符串当作哈希表的键，同一个键下的字符串就是一组。另一种键是 26 个字母各自出现的次数。本文用真实数据展示"用字符集合当键"会丢掉什么，实测排序键与计数键的耗时在字符串长度不同时的差别，给出五种语言的实现，并把哈希分组的过程做成分步演示。

题意与示例

陷阱：用字符集合当键，会丢掉出现次数

一个容易想到的错误：用字符串里有哪些字母（集合）当键。但异位词要求每个字母出现的次数也相同，集合把次数丢掉了。下面是真实结果：

真实实测 · 本机执行输出
输入 ['aab', 'abb', 'ab', 'abab', 'ba']
用字符集合当键: [['aab', 'abb', 'ab', 'abab', 'ba']]
solve（排序后的字符串当键）: [['aab'], ['abb'], ['ab', 'ba'], ['abab']]

aab、abb、ab、abab、ba 里，字母种类都是 a 和 b，用集合当键把它们全部分到了同一组，而实际上 aab、abb、abab 各自独立，只有 ab 和 ba 是异位词。

排序后的字符串当键：五种语言的实现

对每个字符串，把它的字符排序得到键，放进哈希表，键相同的字符串放在同一个列表里，最后取出所有列表。Python 用字典，Java 用 LinkedHashMap（保持首次出现的顺序），Go 用"键到结果下标"的映射加切片（这样输出顺序是确定的，不依赖 Go 的 map 遍历顺序），JavaScript 用 Map，C++ 用 unordered_map 记录下标。Python、Java、Go、JavaScript、C++ 都是真实编译运行的。

Python · 解法代码def solve(strs): groups = {} for s in strs: key = "".join(sorted(s)) # 字母异位词排序后完全相同，把它当作分组的键 groups.setdefault(key, []).append(s) return list(groups.values())

Java · 解法代码class Solution { public List<List<String>> groupAnagrams(String[] strs) { Map<String, List<String>> groups = new LinkedHashMap<>(); for (String s : strs) { char[] cs = s.toCharArray(); Arrays.sort(cs); // 字母异位词排序后完全相同，把它当作分组的键 groups.computeIfAbsent(new String(cs), k -> new ArrayList<>()).add(s); } return new ArrayList<>(groups.values()); } }

Go · 解法代码import "sort" func groupAnagrams(strs []string) [][]string { index := map[string]int{} // 排序后的字符串 → 它在 res 里的位置 res := [][]string{} for _, s := range strs { b := []byte(s) sort.Slice(b, func(i, j int) bool { return b[i] < b[j] }) // 字母异位词排序后完全相同，把它当作分组的键 key := string(b) if k, ok := index[key]; ok { res[k] = append(res[k], s) } else { index[key] = len(res) res = append(res, []string{s}) } } return res }

JavaScript · 解法代码function groupAnagrams(strs) { const groups = new Map(); for (const s of strs) { const key = s.split("").sort().join(""); // 字母异位词排序后完全相同，把它当作分组的键 if (!groups.has(key)) groups.set(key, []); groups.get(key).push(s); } return [...groups.values()]; }

排序当键 vs 计数当键

如果字符串只包含小写字母，还可以用 26 个字母各自出现的次数（一个长度 26 的元组）当键，避免排序。排序的代价是 O(L log L)（L 是字符串长度），计数是 O(L)。我造了 2000 个字符串，每个都是从 10 个基础串之一随机打乱得到，保证有大量异位词，在三种长度下比较两种键的耗时（每个取三次中最快的一次），并确认分组结果一致：

真实实测 · 本机执行输出
每个字符串长度为 L 的 2000 个随机小写字符串（每个字符串取自其中一个 10 个基础串的随机排列，保证有大量异位词）：排序当键 vs 计数当键
L=  10: 排序当键     0.90 ms    计数当键     1.25 ms    分组一致=True（共 10 组）
L= 100: 排序当键    12.39 ms    计数当键     6.23 ms    分组一致=True（共 10 组）
L=1000: 排序当键   160.10 ms    计数当键    55.40 ms    分组一致=True（共 10 组）

字符串很短时（L = 10），排序当键更快（0.90ms 对 1.25ms），因为计数需要建一个 26 长度的数组再转成元组，固定开销更大；字符串更长时计数当键更快：L = 100 时 12.4ms 对 6.2ms，L = 1000 时 160.1ms 对 55.4ms（约 2.9 倍）。这只是 Python 里的实测，其他语言里排序和计数各自的相对开销可能不同。
