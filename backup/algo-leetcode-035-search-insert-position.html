LeetCode 35. 搜索插入位置

给定一个升序、元素互不相同的数组和一个目标值：如果目标在数组里就返回它的下标，否则返回它按顺序应该插入的位置。换个说法，就是"第一个大于等于 target 的位置"，都比 target 小就是数组长度。这是二分查找最标准的形态，也是后面所有二分变体的基础：左闭右开区间 [lo, hi)，nums[mid] < target 时丢掉左半，否则丢掉右半。这道题里最值得实测的是一个几十年的老坑：(lo + hi) / 2 在整数溢出时会算出负数。本文用真实的 Java 和 C++ 程序展示它，给出五种语言的实现，并把二分做成分步演示。

陷阱：(lo + hi) / 2 会溢出

32 位有符号整数的最大值约 21.47 亿。当数组很长、lo 和 hi 都很大时，lo + hi 可能超过这个范围，回绕成负数，再除以 2 得到的中点是负的，会导致数组越界。下面直接取 lo = 15 亿、hi = 20 亿 做计算（真实的数组要超过 20 亿个元素才会出现这种情形，但两个整数相加的行为是一样的）：

真实实测 · 本机执行输出
lo = 1500000000，hi = 2000000000（数组长度超过 20 亿时才会真的出现，这里直接对两个整数做计算）：
Java: (lo + hi) / 2 = -397483648
Java: lo + (hi - lo) / 2 = 1750000000
C++ (按 int 相加回绕后再除 2): -397483648
C++ lo + (hi - lo) / 2 = 1750000000
Python（整数不会溢出）: (lo + hi) // 2 = 1750000000

Java 的 (lo + hi) / 2 得到 -397483648，一个负数，而 lo + (hi - lo) / 2 得到正确的 1750000000。C++ 里有符号整数溢出是未定义行为，我用无符号加法模拟了回绕的结果，同样得到了 -397483648，再用 lo + (hi - lo) / 2 得到 1750000000。Python 的整数不会溢出，所以没有这个问题。本文所有语言里都把中点写成 lo + (hi - lo) / 2，它在 lo、hi 都是非负整数时不会溢出。

左闭右开二分：五种语言的实现

搜索区间是 [lo, hi)，初始 lo = 0、hi = n，答案可能是 n（都比 target 小），所以 hi 取 n 而不是 n - 1。循环条件 lo < hi：取中点，nums[mid] < target 说明 mid 及左边都太小，lo = mid + 1；否则 mid 可能就是答案，hi = mid，注意不是 mid - 1。区间为空时 lo == hi，它就是第一个大于等于 target 的位置。Python、Java、Go、JavaScript、C++ 都是真实编译运行的。

Python · 解法代码def solve(nums, target): lo, hi = 0, len(nums) # 搜索区间是左闭右开 [lo, hi)，答案可能是 len(nums) while lo < hi: mid = lo + (hi - lo) // 2 # 写成 lo + (hi - lo) / 2，避免 lo + hi 溢出 if nums[mid] < target: lo = mid + 1 # mid 太小，答案在它右边 else: hi = mid # mid 满足 >= target，它可能就是答案 return lo

Java · 解法代码class Solution { public int searchInsert(int[] nums, int target) { int lo = 0, hi = nums.length; // 搜索区间是左闭右开 [lo, hi)，答案可能是 nums.length while (lo < hi) { int mid = lo + (hi - lo) / 2; // 写成 lo + (hi - lo) / 2，避免 lo + hi 溢出 if (nums[mid] < target) lo = mid + 1; // mid 太小，答案在它右边 else hi = mid; // mid 满足 >= target，它可能就是答案 } return lo; } }

目标取 n（大于数组里的所有元素），这是二分要走完整个区间收缩过程的情形。基准（数一数比 target 小的元素）是线性的，每个规模取三次中最快的一次：
