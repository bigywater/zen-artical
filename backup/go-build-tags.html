构建标签与条件编译:文件后缀和 //go:build 的匹配规则

条件编译在 Go 里靠“文件级”的约束完成:文件名后缀与文件顶部的 //go:build。这篇不靠记忆,用 go list 与 go run 在不同平台与标签下看哪些文件被选中,再列出 tag 全集,最后看 go vet 能帮你抓住哪些书写错误。

一个文件参与编译,要同时满足:文件名后缀(_linux、_arm64、_linux_arm64)与顶部的 //go:build 表达式。名字里没有下划线的 windows.go 不算后缀,所以到处都选中;_test.go 只在测试时参与。上表可以直接当成检查清单:改一个文件名或约束之后,用 go list -f '{{.GoFiles}}' 在目标平台上看一遍。

go run 与 ignore

实测 · 本机执行输出 
  go run .:文件名后缀 _darwin | 文件名后缀 _arm64 | 正式版本 | unix 家族
  go run -tags debug .:文件名后缀 _darwin | 文件名后缀 _arm64 | debug 版本 | unix 家族
  go run tool.go(显式给出的文件,//go:build ignore 不再生效):go run tool.go 才会用到

//go:build ignore 是写“只供 go run 的小工具”的惯用法:按包构建时它不参与,显式 go run tool.go 时命令行给出的文件直接使用,不再检查约束。

go vet 能帮什么

实测 · 本机执行输出 
  go vet:rc=1
    a.go:3:1: misplaced //go:build comment
    b.go:2:1: +build lines do not match //go:build condition
  go list(darwin 本机):选中 | 排除 = [a.go]|[b.go c.go]

最常见的两个错误:把 //go:build 写到 package 之后(不生效,还没有编译错误,只有 vet 会告诉你),以及新旧两种写法互相矛盾。gofmt 会自动让两者保持一致;建议新代码只写 //go:build。
