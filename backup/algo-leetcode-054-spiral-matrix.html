LeetCode 54. 螺旋矩阵

给定一个 m × n 的矩阵，按顺时针螺旋的顺序返回所有元素：先走最上面一行从左到右，再走最右边一列从上到下，再走最下面一行从右到左，再走最左边一列从下到上，然后向里缩一圈，重复。这道题没有算法上的窍门，难点是边界：当剩下的区域只有一行或一列时，"下边"和"左边"会重复走已经走过的格子。本文用真实运行展示漏掉这个判断的后果，实测耗时，给出五种语言的实现，并把逐圈走的过程做成分步演示。

陷阱：只剩一行或一列时，下边和左边会重复

每一圈按上、右、下、左四条边走。当剩下的区域只有一行时，"上边"已经走完了整行，"下边"与"上边"是同一行，再走一遍就重复了；只有一列时，"右边"走完了整列，"左边"与它重复。所以只有区域至少有 2 行、2 列时，才需要走下边和左边。下面是每圈无条件走四条边的写法与 solve 的真实结果：

[[1, 2, 3]] 无条件走四条边得到 [1, 2, 3, 2, 1]：上边走完 1、2、3，"下边"又从右往左走了一遍 2、1；[[1], [2], [3]] 得到 [1, 2, 3, 2]。而 2×3 和 3×3 的矩阵，没有这个问题（最后一圈区域是完整的至少 2 行 2 列，或者是中间的一个格子），两种写法结果相同。所以这个错误只在只有一行、一列，或者收缩到最后只剩一行、一列时才暴露。

逐圈收缩：五种语言的实现

用 top、bottom、left、right 表示还没走过的矩形区域。每一圈：先走上边（第 top 行，从 left 到 right）；再走右边（第 right 列，从 top + 1 到 bottom）；如果 top < bottom 并且 left < right（至少 2 行 2 列），再走下边（第 bottom 行，从 right - 1 到 left）和左边（第 left 列，从 bottom - 1 到 top + 1）；然后四条边各向里缩一格。Python、Java、Go、JavaScript、C++ 都是真实编译运行的。

Python · 解法代码def solve(mat): res = [] top, bottom, left, right = 0, len(mat) - 1, 0, len(mat[0]) - 1 # 还没有走过的矩形区域的四条边 while top <= bottom and left <= right: for j in range(left, right + 1): # 上边，从左到右 res.append(mat[top][j]) for i in range(top + 1, bottom + 1): # 右边，从上到下 res.append(mat[i][right]) if top < bottom and left < right: # 只有区域至少 2 行 2 列时，才有下边和左边 for j in range(right - 1, left - 1, -1): # 下边，从右到左 res.append(mat[bottom][j]) for i in range(bottom - 1, top, -1): # 左边，从下到上 res.append(mat[i][left]) top, bottom, left, right = top + 1, bottom - 1, left + 1, right - 1 # 向里收缩一圈 return res

Java · 解法代码class Solution { public List<Integer> spiralOrder(int[][] matrix) { List<Integer> res = new ArrayList<>(); int top = 0, bottom = matrix.length - 1, left = 0, right = matrix[0].length - 1; // 还没走过的矩形区域的四条边 while (top <= bottom && left <= right) { for (int j = left; j <= right; j++) res.add(matrix[top][j]); // 上边，从左到右 for (int i = top + 1; i <= bottom; i++) res.add(matrix[i][right]); // 右边，从上到下 if (top < bottom && left < right) { // 只有区域至少 2 行 2 列时才有下边和左边 for (int j = right - 1; j >= left; j--) res.add(matrix[bottom][j]); // 下边，从右到左 for (int i = bottom - 1; i > top; i--) res.add(matrix[i][left]); // 左边，从下到上 } top++; bottom--; left++; right--; // 向里收缩一圈 } return res; } }

Go · 解法代码func spiralOrder(matrix [][]int) []int { res := []int{} top, bottom, left, right := 0, len(matrix)-1, 0, len(matrix[0])-1 // 还没走过的矩形区域的四条边 for top <= bottom && left <= right { for j := left; j <= right; j++ { // 上边，从左到右 res = append(res, matrix[top][j]) } for i := top + 1; i <= bottom; i++ { // 右边，从上到下 res = append(res, matrix[i][right]) } if top < bottom && left < right { // 只有区域至少 2 行 2 列时才有下边和左边 for j := right - 1; j >= left; j-- { // 下边，从右到左 res = append(res, matrix[bottom][j]) } for i := bottom - 1; i > top; i-- { // 左边，从下到上 res = append(res, matrix[i][left]) } } top, bottom, left, right = top+1, bottom-1, left+1, right-1 // 向里收缩一圈 } return res }

耗时实测

矩阵边长 n 分别为 100、300、1000、2000（n × n 个元素），每个规模取三次中最快的一次：

真实实测 · 本机执行输出
边长 n（n×n 矩阵） | 暴力解 | 本文解法
       100 |     4.724 ms | 0.196 ms
       300 |   109.857 ms | 1.432 ms
      1000 |      （未测，太慢） | 30.139 ms
      2000 |      （未测，太慢） | 176.959 ms

本文解法访问每个元素一次，是 O(元素个数)，边长每翻一倍元素个数变成 4 倍：从 1000 到 2000，耗时增长约 5.9 倍，比 4 倍略高，从 100 到 300（元素 9 倍）增长约 7.3 倍，从 300 到 1000（元素 11 倍）增长约 21 倍，有波动，我没有细究，可能与大矩阵的缓存行为有关，这只是猜测。基准解每取一行就要把整个剩下的矩阵旋转一次，是 O(n³)：从 100 到 300（3 倍）增长约 23 倍（27 倍是立方），所以基准在更大的规模上没有再测。
