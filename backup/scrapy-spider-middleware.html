Spider 中间件:它夹在引擎和 spider 之间做了什么

爬虫中间件夹在引擎和 spider 之间,管的是“进入回调的响应”和“回调产出的请求与 item”。这篇用三个自定义中间件加记录钩子,把输入、输出、异常三条链的方向与短路规则一条条实测出来。

在 process_spider_input 里抛异常会跳过回调和更靠后的 input 方法,Failure 直接交给请求的 errback。HttpErrorMiddleware 就是这么拒绝非 2xx 响应的。

回调抛异常后,各中间件的 process_spider_exception 依次被调用:返回 None 交给下一个,返回可迭代对象则终止异常链,内容只经过更靠近引擎的 output。

异步要求

实测 · 本机执行输出 
  只有同步版本的 Old: TypeError: Middleware spider.Old doesn't support asynchronous spider output. Its process_spider_output() method should be an async generator function or it should additionally define a process_spider_output_asy
  同步 + process_spider_output_async 的 New: 正常运行,item_scraped_count=1,[{'what': 'async 版本被调用', 't': 161.3}]

2.19 不接受只有同步 process_spider_output 的中间件:要写成 async 生成器,或再定义 process_spider_output_async。
