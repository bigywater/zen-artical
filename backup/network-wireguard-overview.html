VPN 隧道的封装:IP-in-UDP 与 MTU 的连锁反应

VPN 隧道把你的包装进另一个包里。多出来的那几十个字节,会把 MTU、分片、丢包率和 TCP 的 MSS 一连串地牵动。这一篇在 Docker 的 Linux 虚拟机里搭了真的 GRE、VXLAN、WireGuard 和 IPsec ESP 隧道,在外层网卡上抓包,把每个包多多少字节、MTU 配错会怎样、丢包怎么被放大、TCP 效率差多少,逐项量出来。

+24 / +50 / +60~72
GRE / VXLAN / WireGuard 每个包额外的字节(实测;ESP 是 +55~56)
1450 vs 1500
VXLAN 指定底层网卡 dev 时接口 MTU 自动是 1450;不指定则是 1500,要自己调
4.6% → 9.2%
10 MB TCP 传输的线上额外开销:不用隧道 4.6%,GRE 6.3%,VXLAN 8.3%,WireGuard 9.2%

  GRE 每个包恒定 +24(外层 IP 20 + GRE 头 4);VXLAN 恒定 +50(外层 IP 20 + UDP 8 + VXLAN 8 + 内层以太网头 14);WireGuard 额外字节随内层大小变化,范围 +60~+72(内层先补零到 16 的倍数);ESP 同样不是常数,范围 +55~+56(填充到 4 字节边界,加 ESP 尾 2 字节)
  内层大小为 16 的倍数时,WireGuard 刚好 +60(外层 IP 20 + UDP 8 + 头 16 + 认证标签 16);不是 16 的倍数的内层包,补到下一个 16 的倍数。IPv6 作外层则每个包多 20 字节(外层 IPv6 头 40,不是 20)——这一点没有测,是计算

GRE 恒定 +24,VXLAN 恒定 +50(含内层以太网头),WireGuard +60~+72、IPsec ESP +55~+56——后两者要把内层包补齐到 16 或 4 字节的倍数,所以随内层大小变化。内层 MTU = 链路 MTU − 额外字节。

接口 MTU

实测 · 本机执行输出 
  g0  默认 MTU 1476
  v0  默认 MTU 1500
  w0  默认 MTU 1420
  v1(VXLAN,指定了底层网卡 dev eth0)MTU 1450;v0(没指定 dev)MTU 1500——后者内核不知道底层是哪块网卡,没有自动减 50 字节,要自己调
  IPsec ESP 在 Linux 里不是一个接口,没有接口 MTU;路径 MTU 由路由和 xfrm 状态推算

内核给 GRE 自动设 1476、WireGuard 1420;VXLAN 只有指定了底层网卡才会自动减 50 字节。隧道接口的 MTU 要和外层链路配套,否则大包会被分片或被丢。

内层包带 DF 就在本地被拒绝(message too long);不带 DF 就先在内层分片、各片再封装。外层分片只在隧道接口 MTU 配得比链路允许的大时出现,而内核会在发出第一个超大包后学到更小的路径 MTU。

  外层 IP 包不能超过 en0 的 MTU 1500:内层 IP 包 ≤ 1500 − 20 − 8 − 32 = 1440 字节时刚好一个包;再大一个字节,外层就被分成两片——分片后任何一片丢失,整个数据报都丢

自己写的 IP-in-UDP 封装:内层 ≤ 1440 字节时外层刚好 1500 字节一个包,1441 字节起外层被分成两片。

丢包放大

实测 · 本机执行输出 
    基线:内层 84 字节                            发 15000 个,丢 149 个 = 0.99%;按公式 1 − 0.99^1 = 1.00%
    内层 1450 字节(1 个外层包)                     发 15000 个,丢 144 个 = 0.96%;按公式 1 − 0.99^1 = 1.00%
    内层 1500 字节(一个请求变成 2 个外层包)              发 15000 个,丢 260 个 = 1.73%;按公式 1 − 0.99^2 = 1.99%

一个内层包变成两个外层包,任何一个丢了都算丢。1% 丢包下实测丢失率约翻倍(0.99% → 1.73%,几轮在 1.7%~2.2% 之间)。

隧道让 MSS 变小、每段多出头部:10 MB 传输的额外开销从 4.6%(不用隧道)升到 GRE 6.3%、VXLAN 8.3%、WireGuard 9.2%。MTU 错配时 TCP 带着 DF,开头几个包付代价后 MSS 降下来,不会一直分片。
