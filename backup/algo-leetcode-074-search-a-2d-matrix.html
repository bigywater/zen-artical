LeetCode 74. 搜索二维矩阵

给定一个 m × n 的矩阵，每一行从左到右升序，并且每一行的第一个数大于上一行的最后一个数。判断目标值是否在矩阵中。这个特殊的排列意味着：把所有行首尾相接，得到的是一个长度 m × n 的升序一维数组。所以可以直接对这个"虚拟"数组做二分查找，一维下标 k 对应第 k / n 行、第 k % n 列（n 是列数）。本文用真实数据展示把 n 写成 m 的后果，实测二分和逐行线性查找的耗时，给出五种语言的实现，并把二分做成分步演示。

陷阱：一维下标换算时把列数写成行数

一维下标换算成二维要除以列数 n：k / n 是行号，k % n 是列号。如果写成了行数 m，在方阵（m = n）上恰好正确，在非方阵上就错了：要么找错格子，要么下标越界。下面是真实结果：

3×4 的官方示例，target = 3 碰巧对了（前几步命中的位置恰好没有错位），但 3×2 和 2×3 的矩阵上，该写法直接下标越界。方阵 2×2 上两种写法结果一致。在随机生成的 20000 个矩阵里（其中方阵只有 3911 个），该写法与正确答案不同（含越界）的有 12240 个，占 61.2%。所以只用方阵测试完全发现不了这个错误。

对虚拟一维数组二分：五种语言的实现

lo = 0，hi = m * n - 1。每一轮取中点 mid，换算出 mat[mid / n][mid % n]：等于目标就返回真；小于目标说明目标在后半，lo = mid + 1；否则在前半，hi = mid - 1。区间为空返回假。整个过程并不真的把矩阵拉平，只是用整除和取余做下标换算。Python、Java、Go、JavaScript、C++ 都是真实编译运行的。

Python · 解法代码def solve(mat, target): m, n = len(mat), len(mat[0]) lo, hi = 0, m * n - 1 # 把矩阵按行首尾相接，看成一个长度 m*n 的升序数组 while lo <= hi: mid = lo + (hi - lo) // 2 v = mat[mid // n][mid % n] # 一维下标 mid 对应第 mid // n 行、第 mid % n 列（n 是列数） if v == target: return True if v < target: lo = mid + 1 else: hi = mid - 1 return False

Java · 解法代码class Solution { public boolean searchMatrix(int[][] mat, int target) { int m = mat.length, n = mat[0].length; int lo = 0, hi = m * n - 1; // 把矩阵按行首尾相接，看成一个长度 m*n 的升序数组 while (lo <= hi) { int mid = lo + (hi - lo) / 2; int v = mat[mid / n][mid % n]; // 一维下标 mid 对应第 mid / n 行、第 mid % n 列（n 是列数） if (v == target) return true; if (v < target) lo = mid + 1; else hi = mid - 1; } return false; } }

逐行查找（这里是 C 实现的 in）随元素个数线性增长，400 万时 35.0ms；二分只需要约 log₂(400万) ≈ 22 次比较，耗时是微秒量级，400 万时约 0.015ms，约 2300 倍。二分的耗时在这个范围内增长得很慢，小规模上的读数受计时精度影响，我没有细究。
