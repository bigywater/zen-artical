编码加压缩的组合矩阵:体积与端到端耗时

编码和压缩是两件事,实际是叠加使用的。把 JSON、MessagePack、Protobuf 与 snappy、lz4、gzip、zstd、brotli 各种组合,在三个数据集上量体积和耗时,看看到底哪种组合在什么情况下最合适。

未压缩时 Protobuf 比 JSON 小 32%(products)、65%(timeseries)、76%(nested)。但压缩之后差距大幅缩小:products 上 zstd-3 的 Protobuf 反而比 JSON 大 3.5%。最小的组合都是 JSON 加高级别压缩(brotli q11 或 zstd-19)。

压缩级别的影响远大于编码格式:zstd-3 对 zstd-19 差约 100 倍,brotli q11 要 8 秒。编码本身,orjson 的 JSON 最快(5.7 ms),从 dict 构造 Protobuf 消息最慢(34.9 ms);解码 Protobuf 最快(9–16 ms)。
