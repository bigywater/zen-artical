RedirectFixedPath:大小写与多余斜杠怎么修正

用户把 /Users/Profile 写成 /users/profile,Gin 默认给 404。打开 RedirectFixedPath 能帮他们改过来,代价是什么?这篇用 10 个写错的 URL 看修正规则,再测打开之后命中和 404 的耗时差别。

10 / 10
打开 RedirectFixedPath 后被 301 修正的错误写法个数(关闭时 0 个)
36 → 137 ns
/nothing/here 这类 404 请求的耗时
38.3 = 38.3 ns
命中路由的耗时,打开前后相同
← 上一篇 RedirectTrailingSlash:301 还是 307

能修什么

实测 · 本机执行输出 
    === RedirectFixedPath = false ===
    GET    /USERS/Profile           → 404
    GET    /hello                   → 404
    GET    /users//profile          → 404
    GET    /users/./profile         → 404
    GET    /users/x/../profile      → 404
    GET    //users/profile          → 404
    GET    /Files/ABC               → 404
    GET    /DIR                     → 404
    GET    /DIR/                    → 404
    GET    /users/PROFILE/          → 404
    === RedirectFixedPath = true ===
    GET    /USERS/Profile           → 301  Location: /users/profile
    GET    /hello                   → 301  Location: /Hello
    GET    /users//profile          → 301  Location: /users/profile
    GET    /users/./profile         → 301  Location: /users/profile
    GET    /users/x/../profile      → 301  Location: /users/profile
    GET    //users/profile          → 301  Location: /users/profile
    GET    /Files/ABC               → 301  Location: /files/ABC
    GET    /DIR                     → 301  Location: /dir/
    GET    /DIR/                    → 301  Location: /dir/
    GET    /users/PROFILE/          → 301  Location: /users/profile

大小写会被改成路由注册时的写法(/hello → /Hello);重复斜杠、./、../ 被 cleanPath 化简;结尾斜杠也一并处理。参数的值不会被改动:/Files/ABC 只把静态的 Files 改成 files,ABC 保持原样。

注意修正后的 301 是给客户端的,浏览器地址栏会变成规范路径。

实现就是 redirectFixedPath 里的几行:先 cleanPath,再在这个方法的树里做不区分大小写的查找(并把 RedirectFixedPath 自己当作“是否顺便修正结尾斜杠”传进去),成功就走 redirectRequest。所以状态码规则与上一篇相同:GET 301,其他方法 307。查找只在当前方法的树里进行,GET 请求不会被修正到一条 POST 路由。

代价只落在 404 上

命中的请求根本不会走到这段代码,耗时不变。每个不存在的路径却要多做一次 cleanPath 和一次不区分大小写的树遍历(并且多一次内存分配),在 1000 条路由的树里,404 从约 36 ns 涨到约 137 ns。对正常流量没有影响;如果会被扫描器、爬虫大量打 404,这点开销才值得注意。
