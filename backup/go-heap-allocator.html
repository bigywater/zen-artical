内存分配器:mcache、mcentral、mheap 与 size class

“Go 的 new 和 make 到底占多少内存”要看分配器:它把小对象按 68 个固定大小的 class 分配,超过 32 KiB 的对象直接从页堆取页。这篇逐个验证:class 表、取整与浪费、tiny 分配器、malloc header、大对象的页取整,以及不同大小的分配耗时(包括一个我没有查明的非单调现象)。

68 个
size class 的数量,8 字节到 32768 字节
640 vs 576
576 字节的数组:含指针时占 640 字节(多 8 字节 header 后落入下一个 class),不含指针 576 字节
1 字节
tiny 分配器下 new(byte) 实际占的堆:16 个共用一个 16 字节块
← 上一篇 GC 停顿:STW 到底停多久,哪几个阶段要停

运行时把 8 字节到 32 KiB 之间的对象分成 68 个固定大小的 class;每个 class 的内存由若干个 8 KiB 页组成的 span 提供,span 里按对象大小切开。class 的步长在小处是 8 或 16 字节,在大处是 1 KiB 以上,表里的“max waste”列给出每个 class 的最大浪费比例(小 class 可高达 87.5%,大多数 class 在 5% 到 30% 之间)。

不含指针、小于 16 字节的对象不独占一个 class 槽,而是顺序放进同一个 16 字节块。实验里 new(byte) 每个只占 1 字节(2 万次分配只多了 1250 个 16 字节块的分配),new(int64) 占 8 字节。放不下第二个的 [9]byte、[12]byte 各占一个 16 字节块。含指针的对象不走 tiny(要给 GC 精确的指针信息)。

malloc header

实测 · 本机执行输出 
  []any 自己每个槽占 16.0 字节(下面的数字已经扣掉)
  [64]*int(512 字节,含指针)           每个对象占堆约 512.1 字节
  [65]*int(520 字节,含指针)           每个对象占堆约 576.0 字节
  [72]*int(576 字节,含指针)           每个对象占堆约 640.0 字节
  [72]int(576 字节,不含指针)           每个对象占堆约 576.0 字节
  [128]*int(1024 字节,含指针)         每个对象占堆约 1152.0 字节
  [128]int(1024 字节,不含指针)         每个对象占堆约 1024.0 字节

常量 MinSizeForMallocHeader 是 512(指针大小 × 指针位数)。含指针且大于 512 字节的对象,实测要多占 8 字节(源码里把它叫 malloc header,内容是什么我没有核对);不含指针的对象没有这个开销。所以 576 字节的含指针数组(加 header 后 584)落入 640 字节的 class,不含指针的只占 576。含指针的大数组/结构体比想象的更占内存。

大于 32 KiB 的对象不走 size class,直接从页堆取整数个 8 KiB 页:33000 字节占 5 页(40960),恰好 40960 也是 5 页,40961 就是 6 页。大对象分配成本高(65536 字节约 3.4 µs),而且零值初始化要清整块内存。

相邻大小的分配耗时并不单调:112 字节 18 ns、128 字节 70 ns、144 字节 23 ns、192 字节 75 ns。可能与不同 class 在 span 中的布局或清零方式有关,但我没有查源码或做对照实验,这里只记录现象。如果你的热路径分配大小恰好落在慢的 class 上,值得在自己的机器上量一量。
