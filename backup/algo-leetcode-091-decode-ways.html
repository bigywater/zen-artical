LeetCode 91. 解码方法

把 A 到 Z 分别编码成 1 到 26，给定一个只含数字的字符串，问一共有多少种方式把它解码回字母序列。同一个字符串可能有多种拆法："226" 可以拆成 2, 2, 6（BBF）、22, 6（VF）、2, 26（BZ）三种。字符 0 是麻烦的来源：它不能单独解码，只能和前面的 1 或 2 组成 10、20。动态规划：dp[i] 表示前 i 个字符的解码方式数，dp[i] 由两部分相加：如果最后一个字符不是 0，可以单独解码，加上 dp[i-1]；如果最后两个字符组成的数在 10 到 26 之间，可以合起来解码，加上 dp[i-2]。本文用真实数据展示不处理 0 的错误，展示不带记忆化的递归调用次数（正好是斐波那契增长），给出五种语言的实现，并把填表做成分步演示。

陷阱：没有处理 0

0 不能单独解码。如果不判断最后一个字符是不是 0，就会把它当成一个合法的单字符；如果对"最后两位"只看数值是否不超过 26，就会把 06、00 当成合法。下面是把 0 当作普通字符的写法（单独解码时不检查是否为 0）与 solve 的真实结果：

动态规划：五种语言的实现

先处理字符串以 0 开头的情形，直接返回 0。用两个变量滚动：prev2 是 dp[i-2]，prev1 是 dp[i-1]，初始都是 1（空串和第一个字符各有 1 种）。对 i 从 1 开始：cur 先记为 0；如果 s[i] 不是 0，cur += prev1；如果 s[i-1] 不是 0 并且 s[i-1]s[i] 组成的两位数不超过 26，cur += prev2；然后滚动 prev2 = prev1、prev1 = cur。最后返回 prev1。Python、Java、Go、JavaScript、C++ 都是真实编译运行的。

Python · 解法代码def solve(s): prev2, prev1 = 1, 1 # prev2 = dp[i-2]，prev1 = dp[i-1]；dp[0] = 1（空串有 1 种解码），前一个位置尚未开始时也记 1 if s[0] == "0": return 0 for i in range(1, len(s)): cur = 0 if s[i] != "0": # 单独解码 s[i]：不能是 0 cur += prev1 if s[i - 1] != "0" and 10 <= int(s[i - 1:i + 1]) <= 26: # 与前一位合起来解码：两位数在 10 到 26 之间 cur += prev2 prev2, prev1 = prev1, cur return prev1

Java · 解法代码class Solution { public int numDecodings(String s) { if (s.charAt(0) == '0') return 0; int prev2 = 1, prev1 = 1; // prev2 = dp[i-2]，prev1 = dp[i-1] for (int i = 1; i < s.length(); i++) { int cur = 0; if (s.charAt(i) != '0') cur += prev1; // 单独解码 s[i]：不能是 0 int two = (s.charAt(i - 1) - '0') * 10 + (s.charAt(i) - '0'); if (s.charAt(i - 1) != '0' && two <= 26) cur += prev2; // 与前一位合起来解码：两位数在 10 到 26 之间 prev2 = prev1; prev1 = cur; } return prev1; } }

Go · 解法代码func numDecodings(s string) int { if s[0] == '0' { return 0 } prev2, prev1 := 1, 1 // prev2 = dp[i-2]，prev1 = dp[i-1] for i := 1; i < len(s); i++ { cur := 0 if s[i] != '0' { // 单独解码 s[i]：不能是 0 cur += prev1 } two := int(s[i-1]-'0')*10 + int(s[i]-'0') if s[i-1] != '0' && two <= 26 { // 与前一位合起来解码：两位数在 10 到 26 之间 cur += prev2 } prev2, prev1 = prev1, cur } return prev1 }

耗时实测

字符串是 n 个 1，n 分别为 10、100、1000、10 万，每个规模取三次中最快的一次，基准是带记忆化的递归（也是线性，但每一步要走递归调用和缓存）：

真实实测 · 本机执行输出
字符串长度 n（全是 1） | 暴力解 | 本文解法
        10 |     0.008 ms | 0.001 ms
       100 |     0.074 ms | 0.014 ms
      1000 |     0.824 ms | 0.179 ms
    100000 |      （未测，太慢） | 214.042 ms

两者都是线性增长。n = 1000 时基准 0.824ms，动态规划 0.179ms，约 4.6 倍，差距来自递归调用的开销。动态规划从 1000 到 10 万（100 倍）增长约 1200 倍，超过线性：因为这里的答案是斐波那契数，n = 10 万时有两万多位，Python 的大整数加法本身也随位数增长；Java、Go、C++ 里题目限制答案在 32 位整数内，所以不会遇到这个问题。基准在 n = 10 万时没有测（递归深度太大）。
