Testcontainers:用真实依赖做集成测试

Testcontainers 的价值在于用真实依赖替代进程内替身。这篇在真实的 Docker 上验证:先要解决 Docker 29 与旧版 Testcontainers 的 API 版本不兼容,再量容器的启动成本、Ryuk 的清理行为、每个测试方法一个容器的代价,最后用真实 PostgreSQL 对照 H2。

HTTP 400
Testcontainers 1.20.4 请求 /v1.32/info,Docker 29.8.2(最低 API 1.40)返回的状态码;-Dapi.version=1.44 或 1.21.4 可解决
719 ms
启动一个 postgres:16-alpine 容器的中位数(第一次含 Ryuk 1222 ms);每个测试方法一个容器 9.4 s,static 容器 1.8 s
4 / 12
合法的 PostgreSQL 语句被 H2 2.3 拒绝的数量(ON CONFLICT DO UPDATE、RETURNING、jsonb、@>)

事务里的 DDL

实测 · 本机执行输出 
  H2 2.3 默认模式:CREATE TABLE 之后 ROLLBACK → 回滚之后表还在(DDL 没有被回滚)
  H2 2.3 MODE=PostgreSQL:CREATE TABLE 之后 ROLLBACK → 回滚之后表还在(DDL 没有被回滚)
  PostgreSQL 16 真实:CREATE TABLE 之后 ROLLBACK → 回滚之后表不存在(DDL 被回滚)

不用容器的隔离

实测 · 本机执行输出 
  模板库里有 orders 表,1000 行;连续 20 次 CREATE DATABASE ... TEMPLATE tpl 的中位数 57 ms(最小 55,最大 59);DROP DATABASE 中位数 30 ms(含 psql 进程启动)
