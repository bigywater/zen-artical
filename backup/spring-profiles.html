Profile 与 profile 组

spring.profiles.active 写在命令行、环境变量、配置文件里谁说了算?@Profile({"dev","!cloud"}) 是「或」还是「且」?profile 组的顺序影响谁覆盖谁?为什么把 spring.profiles.active 写进 @PropertySource 没有用?这篇在 Spring Boot 4.0.8 上逐个场景实测。

9 个 Bean
逐个激活 profile 对照 @Profile 的 9 种写法;激活 dev 时 5 个生效,激活 prod 时只剩 1 个
prod → proddb, prodmq
group.prod=proddb,prodmq 激活 prod 得到 [prod, proddb, prodmq],app.v 来自靠后的 prodmq;顺序反过来就是 proddb
0 个
写在 @PropertySource 文件里的 spring.profiles.active=dev:getProperty 读得到 dev,激活的 profile 是 0 个

命令行 > 系统属性 > 环境变量 > 配置文件;include 和 additionalProfiles 追加在前面;default 只在没激活任何 profile 时才用。

profile 组

实测 · 本机执行输出 
  spring.profiles.group.prod=proddb,prodmq,激活 prod:
    active=[prod, proddb, prodmq] default=[default]
    app.v = mq ←| 'file:[application-prodmq.properties]'
    db.url = jdbc:prod ←| 'file:[application-proddb.properties]'
    mq.host = prodmq ←| 'file:[application-prodmq.properties]'
  顺序反过来 spring.profiles.group.prod=prodmq,proddb:
    active=[prod, prodmq, proddb] default=[default]
    app.v = db ←| 'file:[application-proddb.properties]'
  不激活 prod(组不会生效):
    active=[] default=[default]
    app.v = null ←| -
    db.url = null ←| -
  spring.profiles.group.prod 写在 application-prod.properties 里(profile 专属文件):
    active=[prod] default=[default]
    app.v = prod ←| 'file:[application-prod.properties]'
  spring.profiles.include=proddb 写在 application-prod.properties 里:
    启动失败(没有 FailureAnalyzer 报告,堆栈里的异常):org.springframework.boot.context.config.InvalidConfigDataPropertyException: Property 'spring.profiles.include' imported from location 'file [application-prod.properties]' is invalid in a profile specific resource [origin: URL [file:application-prod.properties] - 2:25]
  组里套组:group.a=b、group.b=c,激活 a:
    active=[a, b, c] default=[default]
    app.v = c ←| 'file:[application-c.properties]'

激活组名时按写的顺序一并激活成员,靠后的覆盖靠前的;组可以套;include 和 group 不能写在 profile 专属文件里。
