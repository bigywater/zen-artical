LeetCode 4. 寻找两个正序数组的中位数

给定两个已经排好序的数组 nums1 和 nums2，求它们合并后的中位数，要求时间复杂度是对数级。把两个数组合并再取中间当然可以（线性时间），对数级的做法是二分：不合并，只找一个"切点"，把两个数组各自切成左右两半，使得两个左半合起来正好是全部元素的前一半，并且左半的最大值不超过右半的最小值。本文实测线性合并和二分切点的耗时差距，演示一个很隐蔽的边界错误（Python 的负下标不会报错，而是悄悄取错值），给出五种语言的实现，并把二分的过程做成分步演示。

题意与示例

思路：在较短的数组上二分找切点

设两个数组长度是 m 和 n（让 m ≤ n），左半部分一共需要 half = (m + n + 1) / 2 个元素。如果在 nums1 里取前 i 个进左半，那么 nums2 里就要取前 j = half - i 个。切对的条件是：nums1 左半的最大值不超过 nums2 右半的最小值，并且 nums2 左半的最大值不超过 nums1 右半的最小值。二分 i：如果 nums1 左半的最大值比 nums2 右半的最小值还大，说明 i 取多了；反过来说明取少了。切对之后，总数为奇数时，中位数是左半的最大值；偶数时，是左半最大值和右半最小值的平均。因为只在较短的数组上二分，时间是 O(log min(m, n))。

陷阱：切点在边界时，"左边没有元素"要用 -∞ 表示

当 i = 0 时，nums1 的左半是空的，"左半的最大值"不存在，应该当作负无穷；i = m 时，"右半的最小值"应该是正无穷。如果偷懒直接写 a[i - 1]，Python 里 i = 0 会变成 a[-1]，不报错，而是悄悄取到数组的最后一个元素。下面是没有哨兵的写法在会触发边界的用例上的真实结果：

五种语言的实现

五种语言都用同样的结构。哨兵的取法不同：Python 和 JavaScript 用 ±Infinity，Java 和 C++ 用 Integer.MIN_VALUE / INT_MIN、INT_MAX（并在偶数情况下先转成 long 再相加，防止两个极值相加溢出），Go 用一个很大的常量。五种语言都是真实编译运行的。

Python · 解法代码def solve(nums1, nums2): a, b = nums1, nums2 if len(a) > len(b): a, b = b, a # 在较短的数组上二分 m, n = len(a), len(b) half = (m + n + 1) // 2 # 左半部分的元素个数（总数为奇数时，左半多一个） INF = float("inf") lo, hi = 0, m while lo <= hi: i = (lo + hi) // 2 # a 的左半取 i 个 j = half - i # b 的左半取 j 个 a_left = a[i - 1] if i > 0 else -INF a_right = a[i] if i < m else INF b_left = b[j - 1] if j > 0 else -INF b_right = b[j] if j < n else INF if a_left > b_right: # a 的左半取多了 hi = i - 1 elif b_left > a_right: # a 的左半取少了 lo = i + 1 else: # 左半的最大值 <= 右半的最小值，切对了 if (m + n) % 2: return float(max(a_left, b_left)) return (max(a_left, b_left) + min(a_right, b_right)) / 2 raise ValueError("输入不是有序数组")

Java · 解法代码class Solution { public double findMedianSortedArrays(int[] a, int[] b) { if (a.length > b.length) return findMedianSortedArrays(b, a); // 在较短的数组上二分 int m = a.length, n = b.length, half = (m + n + 1) / 2; int lo = 0, hi = m; while (lo <= hi) { int i = (lo + hi) / 2, j = half - i; // a 的左半取 i 个，b 的左半取 j 个 int aL = i > 0 ? a[i - 1] : Integer.MIN_VALUE, aR = i < m ? a[i] : Integer.MAX_VALUE; int bL = j > 0 ? b[j - 1] : Integer.MIN_VALUE, bR = j < n ? b[j] : Integer.MAX_VALUE; if (aL > bR) hi = i - 1; else if (bL > aR) lo = i + 1; else { int left = Math.max(aL, bL); if ((m + n) % 2 == 1) return left; return (left + (long) Math.min(aR, bR)) / 2.0; } } throw new IllegalArgumentException("输入不是有序数组"); } }

复杂度实测：二分不随数组长度线性增长

下面比较的"暴力解"是把两个数组拼起来再排序取中间。这里两个数组交错排列（一个全是偶数，一个全是奇数），每个规模取三次中最快的一次：

真实实测 · 本机执行输出
每个数组的长度 n | 暴力解 | 本文解法
      1000 |     0.023 ms | 0.001 ms
     10000 |     0.157 ms | 0.001 ms
    100000 |     1.542 ms | 0.002 ms
   1000000 |    21.590 ms | 0.011 ms

数组长度扩大 1000 倍（从 1000 到 1000000），暴力解耗时从 0.019ms 涨到 21.9ms，约 1150 倍，基本是线性；二分解法从 0.001ms 涨到 0.012ms，不到 12 倍，远小于线性。前几个规模的二分耗时已经接近计时器的分辨率（0.001ms），所以这里不能用这些数字去拟合出严格的对数曲线，只能说明"远慢于线性增长"。
