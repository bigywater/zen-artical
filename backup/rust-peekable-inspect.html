peekable、inspect 与调试

写解析器经常需要「看一眼下一个元素再决定」,调试迭代器链又需要「看一眼中间的值」。Peekable 和 inspect 分别解决这两件事。这篇用计数器验证 peek 的真实行为,用词法分析对比 take_while,并用 inspect 看清链的执行顺序。

peek 的真实行为

实测 · 本机执行输出 
  编译:成功
  运行(退出码 0):
    刚创建:源已产出 0 个
    peek -> Some(1),源已产出 1 个
    再 peek -> Some(1),源已产出 1 个(没有再拉)
    next -> Some(1),源已产出 1 个(返回的是缓存的 1)
    next -> Some(2),源已产出 2 个
    peek_mut 改成 99: Some(99)
    size_of Peekable<Range<i32>> = 16 字节(Range 本身 8)
