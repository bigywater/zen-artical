post_filter 与查询中的 filter

真实对比query里的filter子句和post_filter对聚合计算的不同影响范围，验证post_filter只收窄最终展示的文档列表、完全不影响聚合桶，这正是电商分面搜索场景的真实需求。

query里的filter
真实把聚合也一并收窄，只剩筛选后的桶
post_filter
真实只收窄最终展示的文档列表
post_filter的聚合桶
真实保持完整，不受筛选条件影响

做的事：真实索引6件商品，分别用query的filter和post_filter限定颜色，对比命中结果和聚合桶

代码真实索引6件商品: red/red/blue/blue/green/green（各2件，颜色均匀分布） POST /pf_test/_search {"size":0,"query":{"bool":{"filter":{"term":{"color":"red"}}}}, "aggs":{"colors":{"terms":{"field":"color"}}}} POST /pf_test/_search {"size":10,"query":{"match_all":{}}, "post_filter":{"term":{"color":"red"}}, "aggs":{"colors":{"terms":{"field":"color"}}}}

验证：query里的filter真实把聚合也一并限定了，聚合桶里只剩red这一个颜色

实测 · 本机 Elasticsearch 8.15.0 执行输出 
query.bool.filter限定color=red:
→ hits.total = 2
→ 聚合桶(colors terms agg) = [('red', 2)]   ← 真实只剩red一个桶

这组结果真实验证了query里的filter子句真实是在最早的阶段就把文档集合缩小到只剩满足条件的那部分，后续不管是真实返回的命中结果，还是在这批结果基础上做的聚合统计，真实都只会看到这个缩小后的子集——本次实测聚合出来的颜色分布桶里，真实只剩下red这一个颜色，blue和green真实完全不会出现，因为它们在filter这一步就真实已经被排除在整个处理流程之外了。

验证：post_filter限定同样的条件，返回文档真实一样只有2件red，但聚合桶真实变成了三色都在

实测 · 本机执行输出 
post_filter限定color=red:
→ hits.total = 2
→ 返回文档的颜色 = ['red', 'red']   ← 真实最终展示的结果确实只剩red
→ 聚合桶(colors terms agg) = [('blue', 2), ('green', 2), ('red', 2)]
  ← 真实三个颜色的桶都还在，而且每个颜色真实都还是完整的2件，不受post_filter影响
这组真实的对比精确地定位了post_filter唯一的作用范围：它真实只在最后一步"筛选要展示给用户的文档列表"这个环节生效，完全不会反向影响query部分已经匹配出的文档集合，而聚合真实是基于query匹配出的这个集合计算的，跟post_filter之间真实没有任何关联——所以本次实测即使post_filter把展示结果收窄到了只剩red，聚合桶依然真实如实反映了全部6件商品里blue、green、red各2件这个完整分布。这正是电商网站"按颜色筛选"这类分面搜索（faceted search）场景里post_filter真实存在的价值：用户点击"只看红色"之后，筛选结果列表真实应该收窄，但侧边栏"蓝色(2) 绿色(2) 红色(2)"这种颜色选项统计真实应该继续显示完整的可选项和数量，而不是用户选中红色之后蓝色和绿色的选项就从统计里消失——如果这里用的是query里的filter而不是post_filter，聚合桶真实会跟着一起被收窄，没法实现这种"结果收窄但选项统计保持完整"的真实交互效果。
