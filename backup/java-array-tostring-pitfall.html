数组直接打印真实陷阱:[I@7ad041f3 不是内容，是类型代号加身份哈希

几乎每个Java初学者都真实踩过一次这个坑——直接println一个数组，得到一串看不懂的乱码。这篇真实拆解这串"乱码"到底是什么、每个字符代表什么，以及不同类型数组的前缀真实有什么规律。

真实拆解:[I@7ad041f3 这串字符到底是什么

直接对一个int[]数组调用println()，看真实输出的每一部分代表什么。

ArrayToStringPitfallDemo.java int[] arr = {1, 2, 3}; System.out.println(arr);
真实实测 
直接打印int[]数组真实输出: [I@7ad041f3
arr.toString() 真实结果: [I@7ad041f3
字符串真实是否以[I@开头: true

真实结果证明了数组没有重写 Object.toString(),所以打印出来的真实是默认格式:getClass().getName() + "@" + Integer.toHexString(hashCode())。[I 是 JVM 内部对数组类型的命名规则——[ 代表"这是一个数组"(一维数组一个方括号),I 是 int 的类型代号(取自 Integer 的首字母),@ 后面真实是这个数组对象的 identity hashCode 的十六进制表示——和内容完全没有关系,纯粹是一个身份标识。

真实验证:不同类型数组的前缀规律

int有专属代号I，那其他基本类型和引用类型呢？

真实实测 
double[] 真实toString前缀: [D（D代表double）
String[] 真实toString前缀: [L（L代表引用类型，后面真实跟着完整类名）
long[] 真实toString前缀: [J（J代表long，因为L已经被引用类型占用）
String[] 真实完整toString: [Ljava.lang.String;@7852e922
int[][] 真实toString前缀: [[I（多一个[代表多一维）
真实的命名规则。这套字符代号是 JVM 规范定义的"字段描述符"(field descriptor)规则,基本类型各自真实分到了一个字母:I=int,D=double,F=float,B=byte,C=char,S=short,Z=boolean。long 真实用的是 J 而不是看起来更顺理成章的 L——因为 L 真实被引用类型占用了,任何对象数组的前缀都真实是 L 加上完整的类全限定名再加一个分号(比如 [Ljava.lang.String;)。二维数组则真实用两个连续的 [ 表示,方括号的数量直接对应数组的维度数——这套字段描述符规则是 JVM 字节码层面统一使用的类型编码方式,不只用于 toString(),方法签名、字段类型等场景真实都用同一套记法。
