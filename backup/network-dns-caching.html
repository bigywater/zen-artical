DNS 缓存与 TTL:负缓存与过期时的行为

DNS 的快慢,一半靠缓存,一半靠 TTL 管着缓存什么时候失效。这篇在本机上看缓存的痕迹:公网解析器给出的 TTL 到底怎么变,负缓存(不存在的名字也会缓存)的时间由谁决定,命中缓存省下多少时间,本机操作系统自己又缓存了什么。有一半的实验结果和教科书上的整齐倒数不一样,我如实写。

负缓存

实测 · 本机执行输出 
  ier….invalid → RCODE NXDOMAIN;授权区 SOA 记录的 TTL = 86400 秒,SOA 里的 minimum 字段 = 86400 秒;负缓存时间 = min(86400, 86400) = 86400 秒
  之后每 3 秒再问同一个名字,授权区 SOA 的 TTL 倒数:[86398, 86400, 86389, 86400](命中负缓存,剩余寿命在减少)
  对照 NODATA:example.net 的 SRV 记录 → RCODE NOERROR、回答 0 条、授权区有 SOA(TTL 1800,minimum 1800);隔 2 秒再问 3 次,SOA 的 TTL:[[1800], [1800], [1800]]——“名字存在但没有这种类型”也会被缓存

不存在的名字(NXDOMAIN)和名字存在但没有这种记录(NODATA)都带 SOA,缓存时间取 SOA TTL 与 minimum 的较小者。

本机缓存

实测 · 本机执行输出 
  example.net(存在)连续 6 次:80.9,0.7,0.3,0.3,0.3,0.3 ms
  随机的不存在子名字 xzo….example.net 连续 4 次(NODATA / NXDOMAIN):2017.2,1.0,0.4,0.3 ms
  随机的 .invalid 名字连续 4 次:127.8,0.7,0.3,0.3 ms

操作系统缓存正向和否定答案,命中时 0.3~1 ms。
