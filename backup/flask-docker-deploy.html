Docker 部署 Flask

把 Flask 放进容器,Dockerfile 里有几处写法决定了镜像大小、构建速度、能不能被访问和日志什么时候出现。本机拉不到 python 基础镜像,所以这篇分两部分验证:与基础镜像无关的构建机制用 Docker Desktop 实际构建(FROM scratch);依赖安装、绑定地址、日志缓冲、权限这些则直接在本机用 Flask 和 gunicorn 做同样的事。需要说明:完整的镜像没有构建过,docker run 也没有执行过。

shell 形式与 exec 形式的 CMD

实测 · 本机执行输出 
  shell 形式 CMD gunicorn ...        镜像里的 Cmd = ["/bin/sh","-c","gunicorn -b 0.0.0.0:8000 app:app"]
  exec 形式 CMD ["gunicorn", ...]    镜像里的 Cmd = ["gunicorn","-b","0.0.0.0:8000","app:app"]

下面是按本篇验证过的规则写的 Flask Dockerfile 的常见形状(这个完整的 Dockerfile 没有被构建过,因为拉不到 python:3.14-slim;每一步的效果在本篇里分别验证过):

FROM python:3.14-slim
ENV PYTHONUNBUFFERED=1
WORKDIR /app
RUN useradd --create-home app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
USER app
EXPOSE 8000
CMD ["gunicorn", "-b", "0.0.0.0:8000", "app:app"]

依赖在源码之前(层缓存)、pip 不留缓存、PYTHONUNBUFFERED、非 root、exec 形式 CMD、绑定 0.0.0.0。
