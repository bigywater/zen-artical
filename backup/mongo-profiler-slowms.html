profiler 与 slowms

慢查询日志和 system.profile 是两回事吗?slowms 到底影响什么?把 profiler 开到级别 2 会拖慢多少?这篇逐个验证。

28
slowms = 5 时 20 次全表扫描产生的 Slow query 日志条数(20 find + 8 getMore)
1.15×
profile 级别 2 相对级别 0 的耗时
4,280
级别 2 跑 18,000 次操作后 4 MB system.profile 里剩下的条数

slowms 与日志

实测 · 本机执行输出 
  阈值 100 ms:跑了 20 次全表扫描后,日志里新增的 "Slow query" 数 = 0
  test> db.setProfilingLevel(0, {slowms: 5})
  {
    was: 0,
    slowms: 100,
    slowinprogms: Long('5000'),
  …(共 7 行)
  阈值 5 ms:同样的 20 次之后,新增 "Slow query" = 28  按命令分: {'find': 20, 'getMore': 8}
  最后一条 find 的 Slow query 日志的字段: ['appName', 'collectionType', 'command', 'cursorid', 'docsExamined', 'durationMillis', 'hasSortStage', 'inUseTrackedMemBytes', 'isFromPriorityPortConnection', 'isFromUserConnection', 'keysExamined', 'locks', 'nBatches', 'nreturned', 'ns', 'numInterruptChecks', 'numYields', 'opid', 'peakTrackedMemBytes', 'planCacheKey', 'planCacheShapeHash', 'planRanker', 'planSummary', 'planningTimeMicros', 'priorityLowered', 'protocol', 'queryFramework', 'queryHash', 'queryShapeHash', 'queues', 'remote', 'reslen', 'storage', 'type', 'wasMarkedNonDeprioritizable', 'workingMillis']
  其中 durationMillis = 15,docsExamined = 50000,planSummary = COLLSCAN,keysExamined = 0,nreturned = 101

超过 slowms 的操作写进 mongod 日志(Slow query),profile 级别为 0 时也会写;日志按操作记,find 和 getMore 各一条,字段包括 durationMillis、docsExamined、planSummary。

capped

实测 · 本机执行输出 
  test> db.system.profile.stats().capped, maxSize
  true 1048576
  test> db.setProfilingLevel(0); db.system.profile.drop(); db.createCollection('system.profile', {capped: true, size: 4 * 1024 * 1024}); db.setProfilingLevel(2); db.system.profile.stats().maxSize
  4194304
  test> db.setProfilingLevel(0)
  { was: 2, slowms: 5, slowinprogms: Long('5000'), sampleRate: 1, ok: 1 }

system.profile 是 1 MB 的 capped 集合;想放大要关 profile、drop、再按大小重建。

开销

实测 · 本机执行输出 
  级别 0:293 ms;级别 1:295 ms;级别 2:337 ms(级别 2 是级别 0 的 1.15 倍)
  级别 2 下一共执行了 (1 次预热 + 5 次) × 3,000 = 18,000 次 findOne
  test> db.system.profile.countDocuments({})  // 级别 2 跑完后,system.profile 是 4 MB 的 capped 集合
  4280

级别 2 让 3,000 次 findOne 从 293 ms 变成 337 ms(1.15 倍),并且旧记录会被覆盖:18,000 次操作后只剩 4,280 条。

slowms = 0 加 sampleRate = 0.1,1,000 次操作只记录了 104 条日志。
