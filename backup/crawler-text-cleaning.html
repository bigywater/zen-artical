文本清洗:nbsp、零宽字符、全角半角

网页文字里藏着一堆看不见或者看起来一样的字符:不间断空格、零宽空格、全角数字和逗号、组合重音。它们让字符串比较、去重和价格解析静默地出错。这篇逐类用 Python 验证,并给出一个清洗函数。

7 对 7
Python 当空白处理的 7 个“空格类”字符(nbsp、全角空格等)与不当空白处理的 7 个 Cf 字符(零宽空格、BOM 等)
12 而不是 12345
不清洗时,正则 ¥\s*([\d,]+) 对「¥１２，３４５」取到的价格
2 对 1
不规范化与 NFC 之后,「café」两种写法放进集合的大小

空白类字符

  零宽连字 U+200D                  Cf    False         否           否       否   U+200D

  例:'Price:\xa0¥100\u200b \u3000 ok\ufeff'.strip() = 'Price:\xa0¥100\u200b \u3000 ok\ufeff';.split() = ['Price:', '¥100\u200b', 'ok\ufeff']——零宽空格和 BOM 留在了结果里,看不见但存在

不间断空格 nbsp、全角空格 U+3000、细空格都被 str.strip()、str.split()、正则 \s 当作空白。零宽空格、零宽连字、BOM、软连字符、方向标记属于 Cf 类,isspace() 为 False,留在文本里——比较、去重、关键词匹配会莫名其妙地失败。

NFKC 的利弊

实测 · 本机执行输出 
  '１２３ＡＢＣ，．'            → NFKC '123ABC,.'            (有变化)
  'ｱｲｳ（ﾊﾝｶｸ）'           → NFKC 'アイウ(ハンカク)'           (有变化)
  '㈱テスト'                → NFKC '(株)テスト'              (有变化)
  '①②③'                 → NFKC '123'                 (有变化)
  'x²+y³'               → NFKC 'x2+y3'               (有变化)
  'ﬁle ﬂow'             → NFKC 'file flow'           (有变化)
  '™ ® ©'               → NFKC 'TM ® ©'              (有变化)
  '１２，３４５．６７円'          → NFKC '12,345.67円'          (有变化)
  '“引号”‘单引号’'           → NFKC '“引号”‘单引号’'           (不变)
  '…'                   → NFKC '...'                 (有变化)
  '——'                  → NFKC '——'                  (不变)
  '～'                   → NFKC '~'                   (有变化)
  '‐ – — −'             → NFKC '‐ – — −'             (不变)
  注意:NFKC 把 "x²+y³" 变成 "x2+y3"(数学含义变了)、把 "①" 变成 "1"、把 "ﬁ" 变成 "fi"、把 "™" 变成 "TM";中文引号、省略号、破折号等有的变有的不变——不要无脑对全文做 NFKC
  中文标点 NFKC 之后:，→, 。→。 ！→! ？→? ：→: ；→; （→( ）→) 【→【 】→】 、→、

NFKC 把全角数字字母和逗号变成半角(１２，３４５．６７円 → 12,345.67円),但同时改变含义:x² 变 x2、① 变 1、™ 变 TM、… 变 ...。只对需要的字段做,不要对全文做。

NFC 与 NFD

实测 · 本机执行输出 
  'café' 与 'café':显示都是 café;==:False;len:4 和 5;NFC 之后相等:True
  韩文 "한글":NFC len=2,NFD len=6,==:False,NFC 之后相等:True
  去重集合:{a, b} 的大小 = 2;规范化后 = 1

带重音的字符可以是一个码点,也可以是“字母加组合符号”;显示一样,== 为 False。去重或比较之前统一成 NFC。

Python 的 int() 接受各种 Unicode 数字(全角、阿拉伯-印度),但不接受全角小数点、千分位逗号、货币符号和“万”。NFKC 能转全角,逗号与符号还要自己处理。

HTML 取文本与清洗函数

实测 · 本机执行输出 
  原始 HTML:'<div class="p"> Price:&nbsp;<b>¥１２，３４５</b><br>half\u200bwidth ｱｲｳ\n   next&#8203;line&emsp;ok <span>a</span><span>b</span></div>'
  text_content():' Price:\xa0¥１２，３４５half\u200bwidth ｱｲｳ\n   next\u200bline\u2003ok ab'
  "".join(itertext()):' Price:\xa0¥１２，３４５half\u200bwidth ｱｲｳ\n   next\u200bline\u2003ok ab'
  xpath string():' Price:\xa0¥１２，３４５half\u200bwidth ｱｲｳ\n   next\u200bline\u2003ok ab'
  " ".join(itertext()):' Price:\xa0 ¥１２，３４５ half\u200bwidth ｱｲｳ\n   next\u200bline\u2003ok  a b'
  clean(text_content()):'Price: ¥12,345halfwidth アイウ nextline ok ab'
  clean(" ".join(itertext())):'Price: ¥12,345 halfwidth アイウ nextline ok a b'
  从清洗后的文本里取价格:12,345 → 12345
  不清洗直接用同一个正则:匹配到 '１２'——Python 的 \d 匹配全角数字,但全角逗号 "，" 不在 [\d,] 里,价格被截断;int('１２') = 12,静默得到了错误的 12 而不是 12345

text_content()、itertext()、string() 都保留不间断空格、零宽字符和全角字符,<br> 不产生分隔。清洗函数的步骤:NFKC(只针对要做的字段)、去掉零宽/软连字符/方向标记、把各种空白折叠成一个空格。不清洗时用 \d 的正则会把全角价格截成 12——这种错误没有任何异常。
