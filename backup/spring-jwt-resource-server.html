JWT 资源服务器:签名验证、时钟偏差与密钥轮换

JWT 资源服务器默认校验了什么、没校验什么?roles 声明为什么 hasRole 不认?时钟偏差有多大容忍?密钥轮换的时候旧令牌会怎么样?这篇在 Spring Boot 4.0.8、Spring Security 7 上自己签令牌、自己起 JWKS 服务逐项实测。

iss 不对也通过
默认的 JwtValidators.createDefault() 只校验时间,别的签发者的令牌返回 200
60 秒
默认时钟偏差容忍:过期 30 秒通过,过期 90 秒 401
旧 key 立即失效
JWKS 换成新 key 之后,k1 令牌马上 401,没有宽限期

JWKS 轮换

实测 · 本机执行输出 
  第 1 步 JWKS = {k1}:k1 令牌 → HTTP 200,/read 用户=alice authorities=[FactorGrantedAuthority [authority=FACTOR_BEARER, issuedAt=2026-10-20T04:23:40.356155Z], SCOPE_read, SCOPE_write]
    此时 JWKS 服务被访问了 1 次
  第 2 步 JWKS 切成 {k2} 之后立刻:k2 令牌(kid 不在缓存里) → HTTP 200,/read 用户=alice authorities=[FactorGrantedAuthority [authority=FACTOR_BEARER, issuedAt=2026-10-20T04:23:40.374228Z], SCOPE_read, SCOPE_write]
    这一步 JWKS 服务又被访问了 1 次
  第 3 步:k1 令牌(k2 令牌触发的那次刷新已经把缓存换成了 {k2}) → HTTP 401,WWW-Authenticate: Bearer error="invalid_token", … error=invalid_token description=An error occurred while attempting to decode the Jwt: Signed JWT rejected: Another algorithm expected, or no matching key(s) found
  第 4 步 等 16 秒之后:k2 令牌 → HTTP 200,/read 用户=alice authorities=[FactorGrantedAuthority [authority=FACTOR_BEARER, issuedAt=2026-10-20T04:23:56.390336Z], SCOPE_read, SCOPE_write]
  第 5 步:k1 令牌(JWKS 里已经没有 k1) → HTTP 401,WWW-Authenticate: Bearer error="invalid_token", … error=invalid_token description=An error occurred while attempting to decode the Jwt: Signed JWT rejected: Another algorithm expected, or no matching key(s) found
    累计 JWKS 服务被访问 4 次
  第 6 步 JWKS 服务宕机:k2 令牌(已缓存) → HTTP 200,/read 用户=alice authorities=[FactorGrantedAuthority [authority=FACTOR_BEARER, issuedAt=2026-10-20T04:23:56.398411Z], SCOPE_read, SCOPE_write]
  JWKS 服务宕机时刚启动的应用:k2 令牌 → HTTP 401,WWW-Authenticate: Bearer resource_metadata="http…

kid 不在缓存时立即重新获取;旧 key 立刻失效;JWKS 宕机时已缓存的 key 可用。
