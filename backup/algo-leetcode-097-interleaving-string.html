LeetCode 97. 交错字符串

给定三个字符串 s1、s2、s3，判断 s3 是否由 s1 和 s2 交错组成：把 s1 和 s2 各自切成若干段，然后把这些段交替地排列，得到 s3；两个字符串内部的字符顺序都不能变。例如 s1 = aabcc、s2 = dbbca 可以交错成 aadbbcbcac。每一步取 s3 的下一个字符，它可能来自 s1，也可能来自 s2，如果两边的下一个字符恰好相同，就要试两种可能，这正是动态规划的场景。dp[i][j] 表示 s1 的前 i 个字符和 s2 的前 j 个字符能否交错成 s3 的前 i + j 个字符：最后一个字符要么来自 s1（需要 s1[i-1] == s3[i+j-1] 且 dp[i-1][j] 为真），要么来自 s2。本文用真实数据展示"两边都匹配时固定选 s1"的贪心为什么不行，展示朴素递归的调用次数，给出五种语言的实现，并把填表做成分步演示。

陷阱：贪心固定优先用 s1，不回溯

一个直觉的写法是：逐个看 s3 的字符，如果 s1 的下一个字符匹配就用 s1 的，否则用 s2 的，一次过扫描，不回溯。但当两边的下一个字符都能匹配时，选哪一边会影响后面能否成功，一旦选错就再也回不去了。下面是这种贪心与 solve 的真实结果：

官方示例（aabcc、dbbca、aadbbcbcac）贪心得到 False，正确答案是 True；aa、ab、abaa 也是：s3 的第一个字符 a 两边都能匹配，贪心固定选了 s1，而正确的交错方式要先用 s2 的 a。ab、ab、abab 和 a、a、aa 里贪心碰巧是对的。在随机的 20000 组数据里（字母只有 a、b，冲突很多），贪心出错的有 1748 组，占 8.7%。

朴素递归的调用次数

朴素递归在每个"两边都匹配"的位置都要分成两支，同一个（i, j）状态会被重复走很多次。最坏的情形是：s1 和 s2 全是 a，s3 是很多个 a 加一个 b（永远无法成功），必须把所有交错的走法都试遍才能断定不行。下面是真实统计的调用次数：

朴素递归的调用次数（s1、s2 全是 a，s3 = a*(2n-1) + b：无法交错成功，必须试遍所有交错方式）：
n= 4: 结果 False，递归调用       181 次，     0.03 ms；动态规划只有 25 个格子
n= 8: 结果 False，递归调用     35749 次，     4.35 ms；动态规划只有 81 个格子
n=10: 结果 False，递归调用    520675 次，    60.44 ms；动态规划只有 121 个格子
n=12: 结果 False，递归调用   7696443 次，   899.17 ms；动态规划只有 169 个格子

n 从 4 到 12，调用次数从 181 增长到 7696443，n = 12 时耗时 899.2ms；每增加 2，大约乘 14 到 15 倍，是指数增长。动态规划只有 (n + 1)² 个格子（n = 12 时 169 个）。

动态规划：五种语言的实现

先检查长度：s1 和 s2 的长度之和必须等于 s3 的长度。用一维数组滚动：dp[j] 表示当前行（s1 用了 i 个）、s2 用了 j 个时能否成功，dp[0] 初始为真。对每个 (i, j)（跳过 (0, 0)）：如果 i > 0，并且 dp[j]（上一行的值，即 dp[i-1][j]）为真，并且 s1[i-1] == s3[i+j-1]，成立；如果 j > 0，并且 dp[j-1]（当前行左边，即 dp[i][j-1]）为真，并且 s2[j-1] == s3[i+j-1]，成立；两者任一成立，dp[j] 为真。最后返回 dp[n]。Python、Java、Go、JavaScript、C++ 都是真实编译运行的。

Python · 解法代码def solve(s1, s2, s3): m, n = len(s1), len(s2) if m + n != len(s3): return False dp = [False] * (n + 1) # dp[j]：s1 的前 i 个字符和 s2 的前 j 个字符，能否交错组成 s3 的前 i+j 个字符 dp[0] = True for i in range(m + 1): for j in range(n + 1): if i == 0 and j == 0: continue ok = False if i > 0 and dp[j] and s1[i - 1] == s3[i + j - 1]: # 最后一个字符来自 s1（dp[j] 还是上一行的值） ok = True if j > 0 and dp[j - 1] and s2[j - 1] == s3[i + j - 1]: # 最后一个字符来自 s2 ok = True dp[j] = ok return dp[n]

Java · 解法代码class Solution { public boolean isInterleave(String s1, String s2, String s3) { int m = s1.length(), n = s2.length(); if (m + n != s3.length()) return false; boolean[] dp = new boolean[n + 1]; // dp[j]：s1 的前 i 个和 s2 的前 j 个字符，能否交错组成 s3 的前 i+j 个 dp[0] = true; for (int i = 0; i <= m; i++) { for (int j = 0; j <= n; j++) { if (i == 0 && j == 0) continue; boolean ok = false; if (i > 0 && dp[j] && s1.charAt(i - 1) == s3.charAt(i + j - 1)) ok = true; // 最后一个字符来自 s1 if (j > 0 && dp[j - 1] && s2.charAt(j - 1) == s3.charAt(i + j - 1)) ok = true; // 最后一个字符来自 s2 dp[j] = ok; } } return dp[n]; } }

Go · 解法代码func isInterleave(s1 string, s2 string, s3 string) bool { m, n := len(s1), len(s2) if m+n != len(s3) { return false } dp := make([]bool, n+1) // dp[j]：s1 的前 i 个和 s2 的前 j 个字符，能否交错组成 s3 的前 i+j 个 dp[0] = true for i := 0; i <= m; i++ { for j := 0; j <= n; j++ { if i == 0 && j == 0 { continue } ok := false if i > 0 && dp[j] && s1[i-1] == s3[i+j-1] { // 最后一个字符来自 s1 ok = true } if j > 0 && dp[j-1] && s2[j-1] == s3[i+j-1] { // 最后一个字符来自 s2 ok = true } dp[j] = ok } } return dp[n] }
