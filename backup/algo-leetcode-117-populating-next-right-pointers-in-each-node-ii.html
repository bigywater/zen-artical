陷阱：照搬116题（完美二叉树）的写法，假设孩子必然成对存在

上一题（116 题）的 O(1) 空间写法里有一步是 head.left.next = head.right，隐含的前提是"只要 head 不是最底层，它就同时有左右两个孩子"——这在完美二叉树里总是成立。但普通二叉树完全可能出现只有左孩子没有右孩子（或者反过来）的结点，直接照搬这行代码，head.right 可能本来就是空的，再对它取 .next 就会崩溃：

真实实测 · 本机执行输出
输入 [1,2,3,4,5,null,7]（结点 2 只有左孩子 4，没有右孩子）\n正确写法（用哨兵逐个判断孩子是否存在）  →  [[1], [2, 3], [4, 5, 7]]\n陷阱写法（照搬116题，假设孩子必然成对存在） →  程序崩溃：AttributeError（对空指针取 .next）

陷阱写法执行到结点 2 时，head.left.next = head.right 把 4.next 设成了 None（因为 head.right 本来就是空的），这一步不会报错；但紧接着 head.right.next = head.next.left 对着一个本来就是 None 的 head.right 取 .next 赋值，直接崩溃。为了确认这不是个例，做了一次随机测试：

真实实测 · 本机执行输出
2,000 组随机二叉树（结点数 2 到 12）：\n照搬116题写法直接崩溃的有 551 组，占 27.6%

超过四分之一的随机树会直接触发崩溃——只要树里出现"只有一个孩子"的结点（这在非完美二叉树里很常见），针对完美二叉树设计的写法就不再成立。正确的做法必须对每个孩子分别判断是否存在，不能假设它们成对出现。

哨兵 + O(1) 空间：五种语言的实现

用一个哨兵结点 dummy 和一个 tail 指针，在遍历当前层（沿着上一层已经建好的 next 指针）的过程中，把下一层遇到的每个孩子（不管是左孩子还是右孩子，只要存在）依次接到 tail 后面——这样不管某个结点有几个孩子，下一层的链都能正确地被串起来。当前层处理完后，下一层的起点就是 dummy.next。时间 O(n)，空间 O(1)（不算递归/输出本身）。Python、Java、Go、JavaScript、C++ 都是真实编译运行的，用同一组 5 个测试用例。

Python · 解法代码def connect(root): node = root while node: dummy = Node(0) # 哨兵，标记下一层已经连出来的链的头 tail = dummy cur = node while cur: if cur.left: # 不能假设孩子一定存在，必须分别判断 tail.next = cur.left tail = tail.next if cur.right: tail.next = cur.right tail = tail.next cur = cur.next node = dummy.next # 下一层的起点 return root

Java · 解法代码class Solution { public Node connect(Node root) { Node node = root; while (node != null) { Node dummy = new Node(0); // 哨兵，标记下一层已经连出来的链的头 Node tail = dummy; Node cur = node; while (cur != null) { if (cur.left != null) { // 不能假设孩子一定存在，必须分别判断 tail.next = cur.left; tail = tail.next; } if (cur.right != null) { tail.next = cur.right; tail = tail.next; } cur = cur.next; } node = dummy.next; // 下一层的起点 } return root; } }
