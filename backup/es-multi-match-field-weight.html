multi_match 的字段权重

真实对比multi_match查询在title和body字段上不加权重、加^3权重的得分变化，并用_explain拆开best_fields与most_fields两种type参数背后真实的max/sum计算公式差异。

不加权重
真实标题命中的文档反而比正文多次命中的得分更高
title^3权重
真实把命中title的那部分得分放大约3倍
best_fields vs most_fields
真实分别是max of和sum of两种计算公式

做的事：真实给title和body两个字段跑multi_match查询，对比不加权重和加^3权重的得分差异

代码doc1: {title:"Learn Python Programming", body:"...not much about python"} doc2: {title:"Java Guide", body:"...covers python programming in depth, python python"} POST /mm_test/_search {"query":{"multi_match":{"query":"python","fields":["title","body"]}}} POST /mm_test/_search {"query":{"multi_match":{"query":"python","fields":["title^3","body"]}}}

验证：不加权重时，标题含1次python的doc1得分反而高于正文含3次python的doc2

实测 · 本机 Elasticsearch 8.15.0 执行输出 
不加权重:
→ doc1(标题含python) score=0.6407243
→ doc2(正文含3次python) score=0.2833101
  ← doc1得分反而更高，尽管doc2里python出现的词频(TF)更多

这组结果真实验证了BM25打分里字段长度归一化的效应：doc1的title字段"Learn Python Programming"只有3个词，doc2的body字段有十几个词，字段越短，单个词项命中带来的相关性权重真实天然越高（这是BM25公式里norm这一项的真实作用）。哪怕doc2里python出现了3次（词频TF更高），字段长度归一化真实依然让doc1这个"标题精简、关键词占比高"的文档得分更高。这也是为什么multi_match不加任何权重时，真实已经不是完全公平地对待每个字段，字段本身的长度特征就已经在悄悄影响结果。

验证：title加^3权重后，doc1得分真实暴涨约3倍，而doc2完全没变

实测 · 本机执行输出 
title^3权重:
→ doc1 score=1.9221733   ← 真实从0.64暴涨到1.92，约等于3倍
→ doc2 score=0.2833101   ← 真实跟不加权重时完全一样，一个数字都没变
这组对比真实证明了^N这种字段权重语法的精确作用范围：它真实只放大"命中这个字段"所贡献的那部分得分，doc1因为真实是在title字段里命中的python，这部分得分被真实乘以3倍，从0.64变成了1.92；而doc2的python是在body字段里命中的，跟title字段的权重设置真实毫无关系，所以得分真实一个小数点都没有变化。这说明字段权重不是"整条查询语句统一放大"，而是真实精确地只作用于"在那个被加权字段上发生的匹配"这一部分计算，没匹配到的字段权重设得再高也真实不会产生任何影响。

真实用_explain对比best_fields（默认，取max）和most_fields（取sum）两种类型的计算方式

代码doc1真实同时命中了title("Python")和body("python")两个字段 POST /mm_test/_explain/1 {"query":{"multi_match":{"query":"python","fields":["title","body"],"type":"best_fields"}}} POST /mm_test/_explain/1 {"query":{"multi_match":{"query":"python","fields":["title","body"],"type":"most_fields"}}}

验证：best_fields真实只取两个字段里分数更高的那个，most_fields真实把两个字段的分数加起来

实测 · 本机执行输出 
type=best_fields（默认）explain:
→ "description": "max of:", value=0.6407243
  ← 真实只取title和body两边得分里更高的那一个（title那边更高）

type=most_fields explain:
→ "description": "sum of:", value=0.82705784
  ← 真实把title和body两边的得分加了起来，比best_fields的0.64更高

这组explain对比真实从底层计算公式的层面证明了multi_match的type参数到底改变了什么：默认的best_fields真实把这次查询当成"在多个候选字段里，只要有一个字段匹配得足够好就行"，所以计算方式真实是max of——只取得分最高的那个字段的贡献，这适合"标题、简介、正文内容基本重复，只是详略不同"这种同一篇文档多字段冗余存储相同信息的场景；most_fields真实把这次查询当成"字段内容各不相同、互为补充"，计算方式是sum of——把每个命中字段的得分真实全部加起来，命中的字段越多，总分真实涨得越多，适合像本文title和body内容本来就不一样的场景。本次实测doc1在两种类型下得分从0.64变成0.83，真实就是因为most_fields真实把title和body两边的贡献都算了进去，而不是只取其中一边。
