debug 与 release 模式的差异

线上为什么一定要 GIN_MODE=release?debug 到底多做了什么?这篇用代码里的三处判断、同一个程序两种模式的真实输出、模式选择的优先级和每个请求的耗时,把这个开关的真实影响列清楚。

Gin 里对 IsDebugging() 的判断只有三类:所有 [GIN-debug] 输出;LoadHTMLGlob 等在 debug 下用每次重新解析的 HTMLDebug;Recovery 在日志里附上请求转储。路由匹配、中间件、绑定等核心路径对两种模式一视同仁。

启动时 debug 会打印默认中间件提示、模式提示、每条路由(方法、路径、handler 名、handler 个数),r.Run 还会打印“信任所有代理不安全”的警告和监听地址。这些输出本身没有害处,但会把配置细节(路由表、handler 名)写进标准输出,也会让测试日志很吵。

模式如何选择

实测 · 本机执行输出 
    GIN_MODE="release" → 启动时 gin.Mode()="release" IsDebugging=false
    SetMode(release) 之后 → "release" IsDebugging=false
    SetMode(test) 之后 → "test" IsDebugging=false
    SetMode("")(空串)→ "debug"
    SetMode("prod") → panic: gin mode unknown: prod (available mode: debug release test)
    GIN_MODE 未设置 → gin.Mode()="debug"
      x_test.go:3: go test 里未设置 GIN_MODE → gin.Mode()="debug"

环境变量 GIN_MODE 在包初始化时读取,代码里的 SetMode 随后覆盖它。没有设置时是 debug——包括 go test 里:实测不设置时 gin.Mode() 也是 debug,而不是源码里似乎设想的 test(init 时测试标志还没注册)。想让测试安静就显式 gin.SetMode(gin.TestMode)。非法的模式名会 panic。

重定向日志

实测 · 本机执行输出 
    debug 模式:DefaultWriter 里收到:
      "[GIN-debug] [WARNING] Running in \"debug\" mode. Switch to \"release\" mode in production."
      " - using env:\texport GIN_MODE=release"
      " - using code:\tgin.SetMode(gin.ReleaseMode)"
      "ROUTE GET /dir/ -> main.main.func2 (1)"
      "[GIN-debug] redirecting request 301: /dir/ --> /dir/"
    release 模式:DefaultWriter 里收到 0 字节

debug 模式每次尾斜杠重定向都会打印一行,但这行里“前后路径”相同,因为打印时请求的路径已经被改写成目标。release 下整行都没有。

性能

实测 · 本机执行输出 
    第 1 轮
      debug    GET /ok   中位 25 ns/请求
      debug    GET /dir  中位 501 ns/请求
      release  GET /ok   中位 25 ns/请求
      release  GET /dir  中位 362 ns/请求
    第 2 轮
      debug    GET /ok   中位 25 ns/请求
      debug    GET /dir  中位 500 ns/请求
      release  GET /ok   中位 25 ns/请求
      release  GET /dir  中位 363 ns/请求

热路径(命中路由)在两种模式下耗时相同。debug 额外付出的是模板的重复解析(见模板一篇,一次渲染相差约 70 倍)、Recovery 的请求转储,以及每次重定向的 debugPrint。所以 release 的意义主要是安静、安全(不泄漏路由表与请求头)和模板性能,而不是路由快了多少。
