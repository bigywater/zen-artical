Fuzz 测试

单元测试只覆盖你想到的输入。Fuzz 测试让程序自己去找:生成输入、观察覆盖率、保留带来新分支的输入再变异。这篇用一个藏了 bug 的小函数,把 cargo fuzz 从建目录到找到崩溃、复现、对比随机测试的过程完整跑一遍。

    本文用到的工具与边界

    • 本机 macOS 27 arm64 / rustc 1.98.1(brew)/ cargo 1.98.1;单个文件用 rustc 直接编译,需要依赖时用 cargo(经代理从 crates.io 下载);计时用 std::time::Instant,数字每次运行会有小幅抖动。nightly 工具链用 rustup 装在隔离目录(不影响 brew 的 rustc):rustc 1.101.0-nightly (21b707e3f 2026-09-30)、miri 0.1.0 (21b707e3f9 2026-09-30)。cargo-fuzz 0.13.2(cargo install --locked,装在隔离目录),libfuzzer-sys 0.4;所有运行固定 -seed=1
    • 没有验证:Linux 上的表现、cargo fuzz coverage 生成覆盖率报告、结构化输入(arbitrary crate)、字典(-dict)、并行(-jobs/-workers)、长时间(小时级)运行能多发现什么、对更长崩溃输入的 tmin 缩减效果
    • 本篇的随机对照是自己写的 xorshift 随机字节生成器,不是任何现成的随机测试工具
