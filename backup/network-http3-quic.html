HTTP/3 与 QUIC:基于 UDP 的传输

HTTP/3 把 HTTP 搬到 QUIC 上,QUIC 又建在 UDP 之上:合并握手、每个流独立丢包恢复、全程加密。这篇用 aioquic 对真实服务器发 HTTP/3 请求,抓包看 QUIC 的包头和 1200 字节填充,量握手省下的一个往返;在本机服务端上实测 0-RTT 再省一个往返;最后在丢包下和 curl + Caddy 的原生实现对照,看 aioquic 的 13 秒慢在哪里。

171 vs 324 ms
QUIC 握手 与 TCP + TLS 1.3 握手 的耗时中位数(example.com)
209 → 105 ms
本机服务端上完整握手与 0-RTT 的响应头耗时,往返 100 ms,省了约一个往返
13189 → 964 ms
3% 丢包下取 10 个 100 KB:aioquic 对 aioquic 与 curl 对 Caddy 的 HTTP/3 耗时中位数(同一时刻 curl 对 Caddy 的 HTTP/2 是 702 ms)

  HTTP/2:TCP 握手 中位 160 ms + TLS 握手 中位 164 ms + 请求到首字节 中位 343 ms;总计 中位 680 ms

QUIC 把传输握手和 TLS 握手合并,1 个 RTT 即可发请求;TCP + TLS 1.3 要 2 个。整次取回首页 348 ms 对 680 ms。

自己的 aioquic 服务端开了 early data 后,0-RTT 请求在握手完成前就发出,响应头 105 ms 对 209 ms,约少一个往返(往返 100 ms)。
